## 16.1 如何区分证据、推断和预测

讨论未来时，最容易犯的错误是把一篇论文的局部实验结果，直接写成整个行业的必然趋势。本章使用三种不同层次：

| 层次 | 本章如何使用 | 不能据此得出的结论 |
|---|---|---|
| 已有机制或证据 | 数学恒等式、原论文中的方法、限定设置下的实验结果 | 任意模型都有效，或某方法必然成为主流 |
| 技术推断 | 根据带宽、格式、误差传播和成本约束推导可能的收益与障碍 | 具体产品发布时间或确定的市场占有率 |
| 未来预测 | 判断哪些问题会更受重视、哪些设计更可能被采用 | 已经发生或已被实验验证 |

下面的“高、较高、中等”是**主观判断强度，不是统计概率**。高把握通常来自稳定的物理、数学或经济约束；具体方法胜负、硬件路线和普及时间的不确定性更大。

论文是否可访问、代码仓库是否存在、是否有可复现 benchmark，也是不同层次的证据。尤其对于近期预印本，应把它们作为研究方向的信号，并结合独立复现和真实部署观察更新判断。

## 16.2 统一目标：把精度看成有限资源

一个部署配置 $\pi$ 至少包含：权重/激活/KV 的格式、分组大小、尺度、保留的高精度部分、必要变换、内核，以及缓存和批处理策略。

可以把选型目标概括为：

$$
\min_{\pi}\ C_{\mathrm{success}}(\pi;\mathcal D,h)
\quad\text{subject to}\quad
\begin{cases}
\operatorname{Quality}_j(\pi)\ge q_j,\\
M_{\mathrm{peak}}(\pi)\le M_h,\\
\operatorname{Latency}_{95}(\pi)\le L_{95}^{\max}.
\end{cases}
$$

这里 $\mathcal D$ 是固定的任务与请求分布，$h$ 是目标硬件，$j$ 表示需要分别约束的任务类别。$C_{\mathrm{success}}$ 的定义见 16.8。这个式子是决策框架，不是已经可被某个优化器精确求解的统一算法。

它带来三个直接结论。首先，同一模型在短对话、长代码生成和长上下文检索上的最优精度可以不同。其次，权重少占的内存可以用于更多 KV、并发或更大的模型，其价值取决于服务需求。最后，平均分合格不一定满足每类任务的底线，不能用大量简单请求掩盖少量关键任务的退化。

因此，我更看好在真实约束下分配精度的方案，而不把位宽单独当作最终目标。

<a id="offline-online"></a>

## 16.3 趋势一：离线优化复杂化，在线执行规整化

**预测：较高把握。** 对重复使用量足够大的模型，离线校准会接受更复杂的搜索与优化；部署端则倾向于使用少量成熟的格式、规整布局和融合内核。

### 已有信号：编码自由度大于部署表示

[FOCUS](https://arxiv.org/html/2608.01847v1) 使用更灵活的编码侧尺度，最终仍保存硬件兼容的 FP4 码字与解码尺度。[SOAR](https://arxiv.org/html/2605.12245v1) 和 [OSFP4](https://arxiv.org/html/2610.08231v1) 从不同角度优化尺度与量化路径。[QServe](https://arxiv.org/html/2405.04532v3) 则说明，中间整数范围和反量化位置会影响实际矩阵乘效率。

这些工作支持一个技术事实：**离线可以探索比最终保存的参数更多的自由度**。不过，搜索更复杂是否值得，仍要看改进能否在真实请求上摊销。

### 为什么工具可能逐渐具有编译器形态

一个较完整的流程会先读取模型结构、硬件能力和业务约束，再决定变换、尺度、码字、位宽与补偿，最后生成特定布局并匹配内核。算法之间的组合会比单个名字更重要。

```mermaid
flowchart LR
    A[模型、硬件与任务约束] --> B[离线选择变换、尺度、码字和补偿]
    B --> C[导出硬件支持的格式与布局]
    C --> D[真实请求验证质量、延迟和成本]
    D -. 测量反馈 .-> B
```

这里“具有编译器形态”是我的预测，不意味着已经存在可以自动找到全局最优量化方案的通用编译器。模型语义、后端能力和校准目标之间仍有大量人工决策。

### 离线优化何时能回本

在质量相当、请求分布固定的条件下，设离线额外成本为 $A$，基线和新配置的每请求平均成本为 $c_0,c_1$：

$$
N_{\mathrm{break-even}}=\frac{A}{c_0-c_1},\qquad c_0>c_1.
$$

所有量必须使用相同成本单位。若 $c_1\ge c_0$，增加调用次数也不会摊销出推理收益。假设额外优化花费 10 GPU·小时、每请求节省 0.05 GPU·秒，在同型号同计价的理想算账下，需要约 72 万次请求回本：

<!-- outlook-example: amortization -->
```python
import math
offline_gpu_seconds = 10*3600
baseline_per_request, quantized_per_request = .20, .15
saving = baseline_per_request-quantized_per_request
break_even = offline_gpu_seconds/saving
assert math.isclose(break_even, 720000)
for requests in (100000, 1000000):
    average = quantized_per_request+offline_gpu_seconds/requests
    print(requests, 'requests: amortized GPU-seconds/request =', round(average, 6))
print('break-even requests =', round(break_even))
```

第一种调用量下，离线成本尚未摊薄；第二种调用量下开始体现净收益。这是成本假设，没有测量任何量化器。模型更新频繁、流量很小、计费粒度较粗或优化后质量不达标时，复杂离线方案可能不划算。

**如何检验预测：** 观察目标硬件上是否持续出现“离线工作增加、运行表示保持兼容、相同质量下端到端成本下降”的结果。如果所谓改进主要依靠更多运行时分支、特殊硬件或不可摊销的校准预算，我会下调其普遍适用性的判断。

## 16.4 趋势二：从局部误差走向行为稳定性

**预测：方向把握较高，具体目标函数的把握中等。** 未来会更重视量化是否保留路由、生成、检索和停止行为，而不是只优化层输出的平均平方误差。

### 相同误差大小，功能影响可以不同

给所有 logits 加同一个常数，MSE 会变化，softmax 却不变。反过来，两个几乎打平的专家只需很小的反向扰动，就可能交换 top-k 位置。这表明误差的方向、相关性和决策间隔都很重要。

设第 $k$ 与第 $k+1$ 个路由 logit 的间隔为 $m$，每个 logit 的扰动绝对值不超过 $\varepsilon$。最小的已选分数最多下降 $\varepsilon$，最大的未选分数最多上升 $\varepsilon$，于是：

$$
\widehat z_{(k)}-\widehat z_{(k+1)}\ge m-2\varepsilon.
$$

因此 $m>2\varepsilon$ 是保持当前 top-k 集合的充分条件。$m\le2\varepsilon$ 只表示失去这个保证，**不意味着必然选错**。实际应用还要估计扰动上界；确定性 top-k 的结论也不能直接替代随机解码的分布分析。

<!-- outlook-example: decision_margin -->
```python
import numpy as np
def softmax(z):
    e = np.exp(z-z.max())
    return e/e.sum()
logits = np.array([2., 1.95, .3])
shifted = logits+10
assert np.allclose(softmax(logits), softmax(shifted))
epsilon = .03
adversarial = np.array([-epsilon, epsilon, 0.])
changed = logits+adversarial
assert logits.argmax() != changed.argmax()
stable = np.array([2., 1.7, .3])
assert stable[0]-stable[1] > 2*epsilon
assert stable.argmax() == (stable+adversarial).argmax()
print('common-shift logit MSE:', np.mean((shifted-logits)**2))
print('decision-changing logit MSE:', np.mean((changed-logits)**2))
print('top-1 before/after:', logits.argmax(), changed.argmax())
```

这个例子中，较大的共同平移不改变概率，较小的定向扰动却改变选择。它不证明 MSE 没有用，而是说明 MSE 应与功能相关的指标共同使用。

### 自回归生成形成反馈

```mermaid
flowchart LR
    A[量化改变当前输出分布] --> B[模型生成不同 token 或选择不同专家]
    B --> C[后续输入与激活分布发生变化]
    C --> A
```

[DRQ](https://arxiv.org/html/2610.11226v1) 针对分布变化下的最坏重建方向，[OnlineQAT](https://arxiv.org/html/2610.09346v1) 在学生生成的前缀上获取教师信号。它们提供了研究信号，但都不能保证解决所有长期生成误差。

我的预测是，校准将更关注靠近决策边界的样本、模型实际访问的状态，以及少见任务上的退化。困难在于，这些目标可能不可导、样本稀少，而且与最终任务成功之间仍有距离。

**如何检验预测：** 同时测路由一致性、生成长度、停止行为、工具参数正确率和最终任务成功率，并在独立任务分布上评估。如果加入行为指标只改善训练样本上的代理目标，却没有改善任务质量，这条具体实现路径就不成立。

## 16.5 趋势三：KV 量化与缓存生命周期联合设计

**预测：对长上下文、高并发和长推理场景把握较高；对所有 LLM 一概成立的把握低。** KV 的保存、读取、共享、迁移与精度会越来越难分开优化。

### 从位宽问题扩展到内存分配问题

内存预算同时容纳权重、KV 与临时工作区。权重量化节省的空间，可以用于更长上下文、更高并发或更大的模型，选择取决于服务目标。

在标准 MHA/GQA、K/V 头维度相同、统一有效位宽的假设下：

$$
M_{KV}\approx 2BLTh_{KV}d_h\frac{b_{eff}}8
+M_{recent}+M_{padding}.
$$

这里 $T$ 只计量化历史前缀；若已把高精度残留计入 $b_{eff}$，就不能再重复加 $M_{recent}$。K/V 使用不同格式时应分别求和。MLA 等压缩注意力结构必须按其实际缓存张量重新算账。

例如同一序列有 32 层、8 个 KV 头、每头 128 维。FP16 缓存每个 token 的纯 payload 为 128 KiB；假设历史缓存的有效位宽为 4.5 bit，并保留最近 512 个 token 为 FP16，1 GiB 的缓存预算可以支持多少 token？

<!-- outlook-example: kv_budget -->
```python
layers, kv_heads, head_dim = 32, 8, 128
values_per_token = 2*layers*kv_heads*head_dim
fp16_bytes = values_per_token*16//8
# Illustrative 4-bit codes + one 16-bit scale per 32 values; no zero point.
effective_bits = 4+16/32
quant_bytes = int(values_per_token*effective_bits/8)
budget = 2**30
recent_tokens, time_group = 512, 32
recent_bytes = recent_tokens*fp16_bytes
history_groups = (budget-recent_bytes)//(time_group*quant_bytes)
history_tokens = history_groups*time_group
total_tokens = recent_tokens+history_tokens
assert recent_bytes+history_tokens*quant_bytes <= budget
assert total_tokens == 27808
print('FP16 capacity:', budget//fp16_bytes, 'tokens')
print('mixed history/recent capacity:', total_tokens, 'tokens')
print('effective KV bits/value:', effective_bits)
```

本例计入声明的尺度和残留区，并按时间组对齐，仍未计分页碎片与其他工作区。这里的有效位宽是示意格式，不是对某个现成 KV 后端的测量。多个并发序列必须共享总预算，不能把总容量当作每条序列容量。

### 动态精度必须配合信息保留

压成 2 bit 后，多个原始数值可能共享同一个编码。仅对这个编码重新用 8 bit 存储，不能恢复已经丢失的信息。若后续需要更高精度，必须另存残差、保留高精度副本或重新计算；这三种方式分别增加存储或计算。

因此，我更看好页、块、层或头级的策略。它们更容易与内核配合，也比逐元素动态切换更容易控制元数据和调度成本。只按年龄降低精度仍然不足：早期的一个事实，可能决定后面的问题。

[OSCAR](https://arxiv.org/html/2605.17757v1) 体现了 Attention 感知目标与缓存布局的结合，[KVarN](https://arxiv.org/html/2606.03458v1) 关注幅度误差积累。不能把这两项工作解释成已经实现了普适的动态精度策略。

**如何检验预测：** 固定总显存与服务质量，比较长上下文任务成功率、并发吞吐、尾延迟和完整缓存占用。若动态判断、格式切换和恢复开销抵消了节省，静态配置可能仍然更优。

## 16.6 趋势四：多种精度体系并存，量化适配向训练前移

**预测：多精度长期并存的把握较高；某个单一位宽统一所有场景的把握低。**

### 不同场景的瓶颈不同

| 场景 | 更可能有价值的方向 | 主要约束 |
|---|---|---|
| 支持原生低精度计算的云端 prefill | FP8、FP4 和受约束混合精度 | 算力利用率、块尺度、累加与布局 |
| 小 batch、带宽受限的解码 | 低位宽权重与高效解码 | 读取量、解包成本、kernel 覆盖 |
| 内存较小的端侧设备 | 2–4 bit、结构化码本与专门内核 | 容量、功耗、指令集与响应延迟 |
| 长上下文、高并发服务 | KV 压缩与缓存管理 | KV 读取、分页、残留区、任务质量 |
| 能承担训练适配成本的模型发布 | QAT、蒸馏、原生低精度训练 | 训练数据、教师成本、优化稳定性 |

这张表是场景判断，不是硬件支持清单。即使权重为 1–2 bit，归一化、激活、KV、累加器和适配器也可能使用不同精度，必须计算整体成本。

### 为什么适配会前移，但 PTQ 仍有长期价值

[QuEST](https://arxiv.org/html/2502.05003v2) 与 [ParetoQ](https://arxiv.org/pdf/2502.02631v2) 表明训练过程可以为低位宽表示做更多适配。与此同时，PTQ 不要求重训完整模型，对已有模型、快速迭代和小使用量场景仍然有吸引力。

我预计模型发布会更常附带量化检查点、校准配方、适配器、硬件要求和后端验证记录。若大量使用集中在少量稳定模型上，适配成本更容易摊销；模型更新频繁或分布变化很快时，这个优势会减弱。

极低位宽也可能需要更大的模型、更多训练 token 或额外补偿，才能达到相同能力。比较“更大低位宽模型”与“更小高位宽模型”时，不能只控制某一个参数，例如只匹配参数量或只匹配最终文件大小。

**如何检验预测：** 在相同部署预算和明确训练预算下比较质量、吞吐与能耗，报告保留高精度的部分。如果原生低位宽方案的优势主要来自更多训练数据或额外参数，就不能把全部收益归因于位宽。

<a id="structure-moe"></a>

## 16.7 趋势五：结构压缩、专家共享和位宽共同优化

**预测：研究价值的把握较高，普遍部署收益的把握中等。** MoE 为联合优化提供了空间，但也引入共享误差和路由偏差。

一种表示可以写为：

$$
W_e\approx A_e\Phi^T+E_e,
\quad A_e\in\mathbb R^{m\times r},\quad
\Phi\in\mathbb R^{d\times r}.
$$

$\Phi$ 是可跨专家共享的输入基，$A_e$ 是专家特有系数，$E_e$ 保留必要残差。此时要共同决定共享秩、系数位宽、残差表示和哪些专家值得额外容量。

[BitsMoE](https://arxiv.org/html/2606.00079v2) 探索共享谱基和分量位宽，[MiLo](https://arxiv.org/html/2504.02658v2) 使用低秩补偿，[DBW](https://arxiv.org/html/2610.06026v1) 将零位剪枝纳入位宽决策。这些方法的目标和约束不同，只能作为联合表示设计的不同信号。

### 共享会减少冗余，也会耦合误差

如果共享基产生误差 $\delta\Phi$，则每个专家都会出现 $A_e\delta\Phi^T$。MoE 输出还是被选中专家的加权和，因此多个专家的误差可能相加、抵消或通过路由选择改变作用范围。

这意味着把每个专家完全独立地量化和评分，可能漏掉共享部分的影响。仅按专家激活频率分配精度也不充分：低频专家可能处理稀有语言、特殊工具或关键长尾任务。

我更看好能够把**共享成本、路由加权误差、稀少专家覆盖与可执行布局**一起考虑的模型。允许每个标量自由选位宽虽然灵活，却可能带来过多标签、分支和不规则访存。

**如何检验预测：** 在相同峰值显存和目标内核下比较，并单独报告稀少专家相关任务。若共享结构打破专家并行、增加通信或让少数共享误差影响所有专家，压缩率上的收益可能无法兑现。

<a id="successful-task-cost"></a>

## 16.8 趋势六：评价每次成功任务的成本

**预测：作为决策原则的把握高，成为统一行业指标的速度不确定。**

### 每 token 更便宜，整次任务仍可能更贵

假设输出阶段的每 token 成本变为原来的 $r_c$，输出长度变为原来的 $r_L$，则该阶段成本比为 $r_c r_L$。例如 $0.7\times1.5=1.05$：单位 token 成本下降 30%，但长度增加 50%，输出阶段总成本增加 5%。

如果输出阶段只占基线单次成本的比例 $f$，并暂时假设其他成本不变，则：

$$
r_{attempt}=(1-f)+fr_cr_L.
$$

这个比例不自动包含排队、前缀缓存变化或外部工具调用。必须按一致的任务边界实测，而不能直接用单个 GEMM 的速度代入。

### 成功任务成本需要质量约束

对独立重复尝试、成功概率 $p>0$ 不变、每次平均成本为 $C$ 的理想模型，预期尝试次数为 $1/p$，因此：

$$
C_{success}=\frac{C}{p},\qquad
r_{success}=r_{attempt}\frac{p_{base}}{p_{quant}}.
$$

现实中的失败可能相关：同一道不会做的题重复尝试仍然失败；失败恢复可能改变 prompt 和成本；重试次数也可能受限。因此生产评价应优先报告固定任务集上的总成本、完成数、失败数及恢复过程，而不是直接套几何分布公式。

<!-- outlook-example: successful_task_cost -->
```python
import math
decode_fraction = .8
token_cost_ratio, length_ratio = .7, 1.5
baseline_success, quantized_success = .90, .85
decode_cost_ratio = token_cost_ratio*length_ratio
attempt_ratio = (1-decode_fraction)+decode_fraction*decode_cost_ratio
success_cost_ratio = attempt_ratio*baseline_success/quantized_success
assert math.isclose(decode_cost_ratio, 1.05)
assert math.isclose(attempt_ratio, 1.04)
assert success_cost_ratio > 1
print('output-phase cost ratio:', round(decode_cost_ratio, 6))
print('attempt cost ratio:', round(attempt_ratio, 6))
print('successful-task cost ratio:', round(success_cost_ratio, 6))
print('increase:', round((success_cost_ratio-1)*100, 3), '%')
```

在这些假设下，每次成功任务的成本约上升 10.1%。这是一个反例算账，不是某种量化方法的测量结果。可打开[交互式成本计算器](../figures/outlook_cost_calculator.html)，改变长度、成本和成功率，观察结论在哪些条件下反转。

### 指标也可能被错误优化

单独追求低成本可以通过放弃困难任务实现；单独追求高成功率也可能无限增加推理预算。因此应该固定请求分布、任务难度分层、质量底线、最大输出和重试预算，并同时报告尾延迟。

我的预测是，量化节省的资源常常会被用于更大模型、更多候选、更长上下文或更高并发。单位成本下降后，总计算消耗不一定下降，必须说明收益最终被用在什么地方。

### 新架构信号：Rubin自适应压缩仍须区分产品描述与可复现算法

<a id="rubin-quantization-outlook"></a>

2026-10-20读取的[NVIDIA Rubin官方技术介绍](https://developer.nvidia.com/blog/inside-the-nvidia-rubin-platform-six-new-chips-one-ai-supercomputer/)描述第三代Transformer Engine的硬件自适应压缩，用于增强NVFP4执行。这里能确认的是厂商公开的硬件方向；本轮尚未获得足以复现该压缩机制的完整编码/训练配方与独立结果，不能给它编造一种新量化算法或沿用宣传峰值作为整模加速。

[PTX 9.4块缩放规范](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html#tcgen05-block-scaling)还列出UE5M3尺度等新增组合，并限定到特定target family。指令新增不自动说明零售GPU映射、软件内核或模型收益已经确认，也不能将某个target名字凭推测绑定到Rubin。纳入研究路线时，先取得架构/指令/后端对应，再建立格式参考解码、真实内核对照和质量—成本曲线。

当前有较完整证据的补充路线已并入[硬件能力矩阵](09_浮点格式与推理系统.md#gpu-architecture-quantization)、[MR-GPTQ与4/6](13_新进展_FP4与误差修正.md#mr-gptq-fpquant)、[原生FP4训练](14_新进展_训练与MoE.md#native-fp4-training)。这些路线表明尺度精度、转置一致性和融合开销会影响算法选择，但不保证下一代设备使用同一配方即可最优。

## 16.9 未来 1–3 年的分场景预测

下面是截至分析日期的判断，时间窗口不是承诺。

| 判断 | 把握 | 主要成立条件 | 应观察的信号 |
|---|---|---|---|
| 硬件原生低精度与规整混合精度继续扩大应用 | 较高 | 内核覆盖、稳定的数值适配、真实端到端收益 | 更多模型在原生内核上满足相同质量底线 |
| 校准更重视状态分布与行为稳定 | 较高 | 可获取代表性任务数据、教师或奖励信号成本可接受 | 任务成功和长推理指标稳定改善，而不仅是层 MSE |
| 长上下文 KV 与分页、保留策略联合优化 | 场景内较高 | KV 是主要成本，元数据和调度开销可控 | 固定显存下完成更多同等质量请求 |
| QAT、蒸馏和原生低位宽适配更早进入发布流程 | 中等至较高 | 使用量能摊销训练适配成本 | 官方检查点附带可复现配方与目标后端数据 |
| 共享结构、低秩与位宽分配组合增多 | 中等 | 节省存储能转化为规整执行，误差耦合可控 | 相同峰值内存下同时改善质量或吞吐 |
| 任意模型都可无条件 W1A1 化并成为通用部署方案 | 低 | 训练、表示能力、硬件和高精度例外均需突破 | 跨模型、跨任务、同等总预算下的独立复现 |
| 逐元素、逐 token 的任意动态位宽普遍采用 | 低至中等 | 决策、恢复、打包和内核切换成本足够低 | 计入全部开销后仍优于块级静态或混合方案 |

若观察窗口扩大到 3–5 年，我更愿意预测“模型结构与低精度训练共同设计会增加”，而不指定某种格式、某家公司或某个位宽最终获胜。硬件路线和模型架构变化都可能改变当前判断。

<a id="research-priorities"></a>

## 16.10 三条值得优先投入的研究路线

### 路线 A：固定硬件格式下的任务感知校准

**研究问题：** 在相同位宽、布局和推理内核下，加入行为稳定或分布鲁棒目标，能否改善独立任务质量？

首先固定一个可稳定运行的基线，记录完整量化配置。对比仅使用重建目标、加入鲁棒项、加入教师或学生状态数据三类设置，尽量保持校准数据和计算预算一致。除整体得分外，还测路由变化、输出长度和结构化输出错误。

最小成功标准是：独立评估集的质量改善可重复，或在质量底线内获得更低总成本；推理端没有新增未计入的操作。若收益只存在于被反复调参的校准集，应拒绝该结果。方向依据见 [DRQ](13_新进展_FP4与误差修正.md#drq)、[FOCUS](13_新进展_FP4与误差修正.md#focus) 与 [OnlineQAT](14_新进展_训练与MoE.md#onlineqat)。

### 路线 B：长推理 KV 的精度、保留与恢复策略

**研究问题：** 在总显存和延迟约束下，哪些历史状态值得更高精度，判断和恢复成本是否值得？

先建立固定精度的 KV 基线，再加入块级精度、残差保留或重算策略。控制模型、prompt、并发和最大生成长度，使用长文档事实提取、多步推理和跨位置检索任务，分别测方向误差、幅度误差与最终成功率。

必须记录量化索引、尺度、页碎片、高精度残留、恢复缓冲和额外计算。若策略需要本应已经丢弃的高精度数据，应把保留或重算路径实现出来后再比较。方向依据见 [KV 与推理系统](15_新进展_KV与推理系统.md)。

### 路线 C：MoE 的路由感知结构与位宽分配

**研究问题：** 共享基、补偿秩和位宽能否在保持稀少专家质量的同时，更好利用设备内存与带宽？

至少比较统一位宽、仅按激活频率分配、按校准误差分配、加入共享结构或路由信息四类方案。统一完整内存上限，避免通过额外高精度补偿偷增预算；分别评估常见任务与稀少专家相关任务。

还要把专家并行、通信和 grouped GEMM 的影响计入服务指标。只有文件变小、但峰值内存或延迟没有改善的结果，不能视为部署收益。方向依据见 [EAQuant](14_新进展_训练与MoE.md#eaquant)、[MiLo](14_新进展_训练与MoE.md#milo) 和 [BitsMoE](14_新进展_训练与MoE.md#bitsmoe)。

<a id="forecast-validation"></a>

## 16.11 如何验证、否定和更新这些判断

### 一个可复用的验证记录

| 项目 | 至少记录什么 |
|---|---|
| 对象 | 模型 revision、架构、tokenizer、目标硬件与后端版本 |
| 配置 | W/A/KV 格式、分组、尺度类型、保留精度、变换与补偿 |
| 数据 | 校准集、开发集与最终评估集，任务分层和长度分布 |
| 成本 | 离线校准/训练、教师调用、总存储、峰值内存、恢复和运行成本 |
| 性能 | TTFT、TPOT、P95/P99 延迟、并发吞吐、完整生成长度 |
| 质量 | 任务成功率、分任务退化、路由/停止/格式错误及重试 |
| 不确定性 | 重复运行、随机种子、置信区间，以及统计方法 |
| 决策 | 是否达到预设质量底线，收益来自哪里，哪些假设失败 |

评估应优先使用相同请求上的配对比较，并预先固定最终测试集。置信区间要考虑任务、样本和随机生成的层次；不要把高度相关的 token 当作独立样本来虚增统计置信度。

### 什么证据会使我改变预测

如果复杂离线优化无法在合理使用量内回本，我会降低对通用自动优化流程的预期；如果行为目标在多任务独立评估中持续无收益，我会降低对该类代理目标的预期；如果缓存架构变化显著降低了 KV 成本，KV 精度管理的优先级也应下降。

反过来，如果某个低位宽方案在同等总预算、多种模型、多个后端和独立团队复现中持续占优，就有理由提高对它的普遍适用性判断。单一模型、单个 kernel 或单篇新预印本通常不足以完成这一步。

建议按季度或在模型/硬件大版本变化后复审。记录预测原文、当时依据、新证据、判断强度变化和适用范围变化，避免事后把原预测改写成永远正确的表述。

| [QuEST](https://arxiv.org/html/2502.05003v2)、[ParetoQ](https://arxiv.org/pdf/2502.02631v2) | 低位宽训练、梯度估计与公平预算比较 | 支持训练适配前移；不提供普适最优位宽 |
| [BitsMoE](https://arxiv.org/html/2606.00079v2)、[MiLo](https://arxiv.org/html/2504.02658v2)、[DBW](https://arxiv.org/html/2610.06026v1) | 共享结构、补偿秩或零位分量与位宽分配 | 支持联合表示设计；跨专家误差与硬件成本仍是限制 |

### 当前证据对研究路线的约束

对未来的判断应按新增对象修正范围：长上下文缓存管理同时包括 MLA 潜变量与循环状态，后者的重复量化需要验证更新保留与尺度反馈，不能只迁移静态 K/V 编码。
无数据的 SINQ/DualQuant 路线值得与激活校准方法做同格式比较，但权重目标的改善不自动证明任务泛化。
MoE 的路由统计只适合作为待验证特征；近期反例与任务感知分配工作共同要求直接敏感性消融。

结构性依据与适用条件见[无数据双轴缩放](04_可学习校准与HQQ.md#sinq-dualquant)、
[MoE 证据对照](14_新进展_训练与MoE.md#moe-sensitivity-evidence)、
[MLA](15_新进展_KV与推理系统.md#mla-quantization)与[循环状态](15_新进展_KV与推理系统.md#recurrent-state-quantization)。
这些工作增加了研究问题，没有使任意架构的统一低位宽、无成本适配或自动最优分配变成已证实结论。

本章最后采用一个可执行的判断标准：在固定任务分布、明确质量底线和目标硬件上，记录一种方案是否降低了成功任务的完整成本，并允许独立证据推翻最初的判断。

```python
feasible_mask = (data[:, 2] >= minimum_quality) & (data[:, 3] <= max_memory) & (data[:, 4] <= max_latency)

assert len(feasible) == 3

# 第 3 步：固定尝试次数N，离线成本也算入总支出。
# 总成本/期望成功数=(offline+N*attempt)/(N*success)，不是单token价格。
for attempts in (1000, 100000, 1000000):
    costs = (feasible[:, 0]+attempts*feasible[:, 1])/(attempts*feasible[:, 2])
    best = int(costs.argmin())
    print('尝试次数:', attempts,
          '各方案GPU秒/期望成功数:', {name: round(float(v), 4) for name, v in zip(names, costs)},
          '选择:', names[best])

# 第 4 步：用方程求精细校准与基线的盈亏点，注意成功率不同也影响门槛。
base, optimized = feasible[0], feasible[2]
saving_per_success = base[1]/base[2]-optimized[1]/optimized[2]
assert saving_per_success > 0
break_even = (optimized[0]/optimized[2]-base[0]/base[2])/saving_per_success
print('相同尝试数量下成功成本的盈亏点:', round(float(break_even)), '次尝试')

# 第 5 步：这是按给定成功率的期望算账，不把所有任务都假设为可独立重试成功。
# 修改 success、请求长度或内存门槛，观察最优方案是否变化；最终需用真实成本替换。
rt.synchronize()
```

</details>

**运行后观察：** 低质量候选被排除；调用量增加时最佳成本方案可能改变，离线优化需要回本量。

**动手修改：** 改变成功率或显存上限，重新计算赢家；不要把假定成功率当作真实测量。

**适用边界：** 假想数据的成本情景，不验证技术趋势预测，也不替代生产成本测量。

### 16-01｜证据、推断、预测（简单｜分类判断，10 分）

给出分类和理由：①某固定版本内核在指定设备与负载下节省20%延迟；②若带宽成为主瓶颈，减小payload可能有利；③未来三年所有模型都会采用同一4-bit格式。

<details><summary>参考答案与评分要点</summary>

**参考路径一：**

①在有可靠实测时是限定条件的事实；②是依赖瓶颈/解码开销的推断；③是范围过大的预测，需硬件、模型和质量证据且不确定性高。不能用一项具体实验直接证明第三项。

**路径二：检查量词。** “指定模型/设备”是有限陈述；“若瓶颈为…”是条件推断；“所有模型/未来三年”是强全称预测。量词扩大需要额外证据。

**反证路径：** 不支持该FP4格式的硬件或质量受损的模型即可使③失败，而不否定①和②。不能用局部事实替全行业预测背书。

**评分要点：** 三分类及条件各3分；跨层推断限制1分。

</details>

<a id="exercise-16-02"></a>

### 16-02｜离线优化的回本量（简单｜计算，10 分）

复杂量化额外花8 GPU小时，每次请求节省0.004 GPU秒；假定同一设备计费口径、无并发摊销变化。需多少请求回本？还有哪些假设需确认？

<details><summary>参考答案与评分要点</summary>

**参考路径一：**

8×3600/0.004=7200000次。需确认质量不退化到需要更多重试、流量足够、设备成本可比、复杂模型更新频率和端到端节省真实；GPU计费时间未必等于单请求墙钟时间。

**路径二：总节省相等。** N请求总省0.004N GPU秒，令它等于28800秒，N=720万。

**方案三：敏感性曲线。** 用节省时间δ与更新周期内流量N比较Nδ和8GPU小时；若δ减半回本量翻倍。硬件单价不同则先换统一货币成本。

**评分要点：** 换单位及结果6分；关键假设4分。

</details>

<a id="exercise-16-03"></a>

### 16-03｜单位 token 便宜，任务可能更贵（困难｜计算，15 分）

输出阶段占基线单次成本80%，量化后该阶段每token成本为原来的0.6，平均长度1.5倍，其余成本不变。基线成功率0.9、量化0.8。在独立重试、成本恒定假设下，求单次与成功任务成本比。

<details><summary>参考答案与评分要点</summary>

**参考路径一：**

单次比0.2+0.8×0.6×1.5=0.92；成功任务成本比0.92×0.9/0.8=1.035，即高3.5%。长度/成功率与成本可能相关，实际应按固定任务集合计成本和成功数，不能盲套独立几何重试。

**路径二：分别计算成功成本。** 将基线每次成本归一为1，则基线1/0.9，量化0.92/0.8=1.15，比值1.035。

**验证路径：以大量固定任务求比率。** 实际应用统计总成本/成功数，并保留失败、重试和长度分布；它可发现成本与成功事件相关导致的理想模型偏差。

**评分要点：** 单次6分；成功成本6分；假设边界3分。

</details>

<a id="exercise-16-04"></a>

### 16-04｜共享前缀的容量收益（困难｜计算，15 分）

同一模型每token完整KV成本0.5 MiB，两个请求各有2048token，其中前1024token可共享。忽略分页碎片与copy-on-write，分别计算不共享与共享的缓存MiB。

<details><summary>参考答案与评分要点</summary>

**参考路径一：**

不共享4096×0.5=2048 MiB；共享唯一token槽为1024+1024+1024=3072，共1536 MiB，减少512 MiB即25%。真实共享按物理块、引用计数与可变尾部管理；不能再把共享收益重复算到每请求里。

**路径二：仅计算重复部分。** 原来共享前缀保存两遍，现在一遍，少1024×0.5=512MiB，从2048减到1536。

**路径三：物理页视角。** 按唯一前缀块加两个私有后缀块计费；真实共享以页边界与copy-on-write为准，不能只按文本字数假定全部前缀可共用。

**评分要点：** 两容量8分；节省4分；物理条件3分。

</details>

<a id="exercise-16-05"></a>

### 16-05｜精度恢复需要保留什么信息（困难｜机制分析，15 分）

某系统将KV从8 bit降为2 bit，之后直接把2-bit值 cast 到8 bit，称为“恢复高精度”。为什么这个说法不成立？什么条件下才可能恢复更多信息？

<details><summary>参考答案与评分要点</summary>

**参考路径一：**

cast只能改变容器/编码，不能恢复量化丢失的细节。需要保留原高精度数据、残差、额外码字或能重新计算原状态的输入/模型路径，并计容量、重算和传输成本；放大bit数不自动增加信息。

**证明路径：多对一映射。** 不同高精度值可能量化到同一码字；只凭码字无法知道原来是哪一个，扩宽容器仍只有同样信息。

**方案三：可恢复设计。** 保存残差/高位细化码或保留输入以重算，才能恢复更多精度；需比较额外信息的存储与重算成本，不能称“免费升bit”。

**评分要点：** 不可逆解释7分；恢复信息来源5分；成本3分。

</details>

<a id="exercise-16-06"></a>

### 16-06｜怎样否定一项趋势判断（困难｜研究设计，15 分）

选择“离线量化会越来越复杂”这一判断，提出适用条件、至少两个可能使你降低信心的证据，以及持续观察指标。

<details><summary>参考答案与评分要点</summary>

**参考路径一：**

适用于模型复用量大、离线预算可摊销且部署格式固定的场景。若模型更新频繁导致无法回本，或简单算法在多模型同预算下持续达到相同质量/延迟，应降低该场景判断。观察额外校准成本、复用量、质量差、导出兼容和真实服务节省；不把一个新算法发表当作普及证据。

**方案二：经济门槛。** 用模型寿命内请求总节省减额外校准成本衡量；若频繁更新使收益持续为负，则该场景不支持复杂化预测。

**方案三：受控长期样本。** 在固定格式、多个模型与任务上追踪简单/复杂方法的独立收益和复现率；发布数量上升只是研究兴趣信号，不等于生产采纳。

**评分要点：** 适用条件4分；反证6分；指标5分。

</details>

<a id="exercise-16-07"></a>

### 16-07｜研究路线与学习任务（困难｜开放题，10 分）

从任务感知校准、长推理KV、MoE位宽分配中选一条，提出三项先修知识和一个两周内可完成的最小研究产出。

<details><summary>参考答案与评分要点</summary>

**参考路径一：**

例：长推理KV先修Attention/softmax误差、流式缓存与分页、统计评测。最小产出可在现有小矩阵和可用模型上对比固定窗口与统一位宽，明确容量账本、边界测试、固定前缀/长生成指标；有硬件才报告性能，无硬件可交机制反例与可复现方案。其他路线按其依赖给具体产出。

**方案二：任务感知校准路线。** 先补优化/二阶统计、语言模型评测、量化导出；两周产出可为同格式两种校准域的配对比较与失败案例。

**方案三：MoE路线。** 先补路由/top-k、混合精度预算、共享误差传播；产出分任务专家覆盖与小规模位宽分配消融。无硬件时完成代理反例，不捏造真实吞吐。

**评分要点：** 先修对应4分；可执行产出4分；资源/证据限制2分。

</details>

<a id="exercise-16-08"></a>

### 16-08｜趋势评测不能靠淘汰难题（困难｜指标审查，10 分）

一个方案通过拒绝困难请求把平均成功成本降低。怎样防止这种指标优化掩盖能力损失？

<details><summary>参考答案与评分要点</summary>

**参考路径一：**

固定请求分布和难度分层，将拒绝、超时、失败及重试计入结果；预设质量/覆盖率底线、最大token和重试预算，报告总成本、成功数、完成率与尾延迟。不能只对被接受的容易样本计算平均成本，再声称对所有任务更划算。

**路径二：拒绝的机会成本。** 总请求固定，将拒绝计为未完成而非从分母剔除，同时限定覆盖率/质量。这样“只挑容易题”不能无代价改善评分。

**方案三：多指标约束。** 先满足分域质量、完成率、延迟和预算，再比较成功任务成本；不存在无条件最大化一个比率就同时提升全部体验的保证。

**评分要点：** 固定分布和失败6分；约束与完整指标4分。

</details>

<a id="exercise-16-e01"></a>

### 16-E01｜一次离线成本如何摊销（简单｜拓展题，单独计分）

额外校准成本100元，每请求节省0.01元。其他条件不变，至少多少请求才能覆盖成本？

<details><summary>参考答案与评分要点</summary>

**解法一：除法。** 100/0.01=10000次恰回本，超过才净节省。

**解法二：总成本差。** ΔC=100−0.01N，要求≤0得N≥10000。

**验证路径：** N=9999仍多0.01元；N=10001省0.01元。前提是质量、重试和请求成本保持题设。

**评分要点：** 单独按 10 分评价：结论与条件 3 分、推理或设计过程 5 分、独立核验与边界 2 分。评分覆盖题干要求的全部子问；未要求比较多解时，可任选或组合参考路径完成作答。数值核验不能替代题干明确要求的证明，多解数量不额外加分。

</details>

<a id="exercise-16-e02"></a>

### 16-E02｜成功率改变后的真实盈亏（困难｜拓展题，单独计分）

基线每次平均成本2元、成功率0.8；量化每次成本1.6元、成功率0.6。用独立恒定成功率重试模型比较成功任务成本，再求量化成功率至少多少才不更贵。

<details><summary>参考答案与评分要点</summary>

**解法一：比值。** 基线2/0.8=2.5元，量化1.6/0.6≈2.6667元，更贵；需1.6/p≤2.5，p≥0.64。

**解法二：批量期望。** 大量独立尝试中总成本/N成功期望的长期比率仍为C/p，得到同门槛；有限样本比率有波动，需测区间。

**边界方案：** 真实失败可能相关、重试成本变化，应以固定任务全集统计成本和成功率，并包含重试上限；0.64不是所有系统的统一阈值。

**评分要点：** 单独按 10 分评价：结论与条件 3 分、推理或设计过程 5 分、独立核验与边界 2 分。评分覆盖题干要求的全部子问；未要求比较多解时，可任选或组合参考路径完成作答。数值核验不能替代题干明确要求的证明，多解数量不额外加分。

</details>

<a id="exercise-16-e03"></a>

### 16-E03｜让资源约束下的预测可被推翻（特别困难｜拓展题，单独计分）

提出“量化节省会降低总能耗”的可检验版本。至少区分固定工作量、固定任务成功数和固定预算三种情景，并说明它们为什么可能给不同结论。

<details><summary>参考答案与评分要点</summary>

**方案一：固定工作量。** 固定模型任务、输入输出token、质量与并发，测总设备能量和端到端时间；省字节不保证省能量，转换/更长运行仍需测。

**方案二：固定成功任务数。** 把重试、失败和恢复的能量计入。单位token能量下降若伴随更长输出或成功率下降，每个成功任务能量可能上升。

**方案三：固定预算。** 省下资源可能用于更多请求、更大模型或更多候选，总能耗可保持预算上限甚至因利用率提高而增加。预测必须预先指定情景、测量边界与拒绝标准，不能从单kernel效率外推社会总消耗。

**评分要点：** 单独按 10 分评价：结论与条件 3 分、推理或设计过程 5 分、独立核验与边界 2 分。评分覆盖题干要求的全部子问；未要求比较多解时，可任选或组合参考路径完成作答。数值核验不能替代题干明确要求的证明，多解数量不额外加分。

</details>

**复习建议：** 计算错误先回到本章的形状、单位与约定；工程判断缺少依据时，补写目标函数、对照配置和验证边界。建议达到 80 分后继续；这是一项自学建议，不是经教学验证的能力认证标准。
