## 1. 高质量论文究竟需要什么

<a id="research-quality"></a>

### 1.1 五项相互关联的要求

| 要求 | 需要回答的问题 | 不充分的替代品 |
|---|---|---|
| 问题价值 | 现有量化在什么真实条件下遇到什么重要限制？ | “这个方法还没有人用于某个模型” |
| 原创贡献 | 相比最接近工作，新增了什么机制、结论、系统能力或测量方法？ | 改名、堆模块、只换超参数 |
| 技术可靠 | 推导、代码和实验是否支持主张？ | 数学排版复杂、代码能跑、局部 MSE 下降 |
| 证据充分 | 优势何时成立、何时失败，能否排除主要替代解释？ | 一个模型、一项指标、一次最好运行 |
| 可检验与表达 | 他人能否复查关键设置、复现实验并理解结论边界？ | 只给汇总图、不公开设置、不能追溯的数字 |

ICML 2026 的评审说明从技术可靠性、表达、重要性与原创性等方面评价论文；原创性也可来自对已有方法的新认识。ICLR 2026 的评审说明同样指出，贡献有价值的新知识并不必然要求刷新 SOTA。因此，**理论、算法、系统、测量分析和可靠的反例研究都可能形成贡献，关键是问题与证据是否匹配**。[ICML 评审说明](https://icml.cc/Conferences/2026/ReviewerInstructions)、[ICLR 评审说明](https://iclr.cc/Conferences/2026/ReviewerGuide)。

### 1.2 先选贡献类型，再安排学习和算力

| 论文主线 | 典型贡献 | 必需的核心证据 | 常见短板 |
|---|---|---|---|
| 量化算法 | 新目标、编码、校准策略或可执行的精度分配 | 强基线、机制解释、受控模型实验、完整表示成本 | 只比弱基线；额外预算未计入 |
| 理论与分析 | 新误差界、条件、等价性、失效机制 | 完整假设与证明；非平凡性；反例或实验连接 | 结论只对无法满足的理想假设成立 |
| 推理系统 | 低比特算子、布局、调度或缓存管理 | 正确性、目标设备实测、瓶颈分析、端到端收益 | 仅小矩阵提速；无服务负载或质量约束 |
| 低比特训练 | 稳定优化、梯度近似、训练配方与资源分配 | 公平总训练预算、收敛与稳定性、部署后质量 | 将额外训练 token 的收益归于位宽 |
| 评测与经验研究 | 揭示被忽视的失效模式、比较偏差或泛化规律 | 明确问题、代表性覆盖、统计方法、可复查协议 | 只有大表格，没有解释或可复用结论 |

不用为了“像一篇顶会论文”强行同时加入新算法、定理、CUDA 内核和新 benchmark。选择一个主要贡献，把支撑链做完整；次要贡献服务于主问题。

### 1.3 从“有改进”到“有知识增量”的四层论证

一个实验数字更好，只能回答某个配置下发生了什么。论文还需要解释该结果为何重要、由什么机制产生、能推广到哪里。可用四层逐步加强主张：

| 层次 | 一个合格的回答 | 还不能推出什么 |
|---|---|---|
| 现象 | 在控制模型、数据和预算后，退化集中出现在某类层或任务 | 不能立即认定是哪种统计特征造成 |
| 机制 | 定向扰动、配对控制或理论分析能区分主要解释 | 不能仅由相关性推出可用的新方法 |
| 干预 | 只改变对应机制，能重复改变预测的中间量和任务结果 | 不能省略额外数据、容量、时间成本 |
| 范围 | 在预定模型/分布/负载上成立，并识别失败条件 | 不能由有限样本推导无条件通用性 |

例如“激活峰值下降了”是现象；“峰值与共享步长造成的误差有关”是机制假设；“在保持格式和容量的条件下调整分组能改善输出”是干预证据；“收益主要出现在跨通道范围失衡且带宽受限的层”是范围说明。这样的链条比单独增加算法模块更容易形成可检验贡献。

**负结果也有价值，但需要明确被否定的命题。** “某次实验没有提高”通常不足；“在给定预算和模型范围内，频率代理不能预测真实敏感性，并给出导致失效的交叉项与可复查实验”则可能增加知识。是否形成足够贡献仍取决于问题的重要性、相关工作和证据强度。

### 1.4 根据论文类型定义最小证据组合

| 主贡献 | 必须做强的部分 | 可合理收窄的部分 | 应主动避免 |
|---|---|---|---|
| 理论 | 非平凡结论、完整条件、证明、与已有界的关系 | 实验可以服务于条件检查和反例，不必拥有完整服务平台 | 用玩具假设声称真实模型性能已获保证 |
| 校准算法 | 最近强基线、同预算、实际导出、独立模型质量 | 若复用相同内核，可重点验证格式一致与开销不增加 | 仅用权重 MSE 或更宽松格式证明优势 |
| 系统 | 数值正确、实际硬件、代表性形状、完整链路与瓶颈 | 可以针对明确设备或架构，无须声称跨全部 GPU | 把布局转换、编译或通信藏在计时区间外 |
| 经验/评测 | 清楚研究问题、代表性覆盖、测量方法、可复查分析 | 不必再强行发明复杂算法 | 把任务榜单扩充或个别失败输出当作解释 |
| 训练 | 优化行为、数据来源、总训练成本、部署后质量 | 可研究小规模受控规律，但结论范围随之限定 | 用不等预训练预算比较“最佳位宽” |

先确定最小证据组合，再决定哪些能力必须自己掌握、哪些可以通过合作补齐。研究投入应优先消除最可能推翻主张的薄弱环节。

## 2. 现有工程能提供什么，还缺什么

<a id="project-gap"></a>

本工程已有量化主线、数学附录、技术示例、研究进展、分级题库和小模型 Notebook，可用作研究入门与排错参考。原工程明确区分教学算例与完整模型/GPU 复现，当前修订 Notebook 的完整 GPU 运行仍需验证。[学习首页](../README.md)、[实验与证据层次](10_实验_评估与选型.md#deep-derivations)。

| 已有基础 | 研究论文仍需补齐的工作 |
|---|---|
| 能解释 GPTQ、AWQ、旋转、码本、QAT、KV 等机制 | 明确最近相关工作和真正未解决的问题 |
| 能完成二维推导与 CPU 数值核验 | 在真实模型与实际格式上建立可信基线 |
| 能区分存储位宽、计算类型和累加类型 | 验证目标后端的真实布局、指令、临时内存与性能 |
| 能完成课程题与参考实验 | 面对没有标准答案的问题，自行形成假设、设计实验并否定它 |
| 有来源导航和技术覆盖 | 对选定细分方向建立持续更新的文献对照，检查同时期工作 |
| 有评测协议与结果包思路 | 获得独立任务、重复运行和完整成本支持的原创结论 |

### 研究准备度自测

- [ ] 能在不看答案时推导一个二阶补偿或尺度优化子问题，解释每个假设。
- [ ] 能指出一个方法的关键代码位置，以及论文公式与实现的对应关系。
- [ ] 能从浮点 checkpoint 完成一次量化、保存、重载与质量评测。
- [ ] 能识别伪量化、真实低比特存储和真实低精度计算的区别。
- [ ] 能解释一项比基线更好的结果还可能由哪些混杂因素造成。
- [ ] 能写出一个最小反例，使某项看似普适的量化结论失效。
- [ ] 能在实验不支持原想法时停止或修改假设，而不是反复挑选有利样本。

这些是本指南建议的准备门槛，不是“全部达标即可投稿”。最有价值的下一步通常是：**选一个窄问题，复现最接近的强基线，同时补足该问题暴露出的知识缺口。**

## 3. 所有方向共用的知识清单

<a id="common-knowledge"></a>

优先级说明：**P0** 表示所有研究方向都应建立工作能力；**P1** 表示选定方向后深入；**P2** 表示由具体问题驱动选学。无需对每项都达到专业数学研究水平，但不能让自己不理解的假设承担论文主结论。

### 3.1 线性代数与数值分析：从“会推”到“推导和实现都可信”

| 优先级 | 具体知识点 | 掌握标准 | 建议完成的验证产出 |
|---|---|---|---|
| P0 | 二次型、PSD/PD、特征值、SVD、谱范数、迹恒等式 | 区分权重 MSE、输入加权误差与最坏方向误差 | 用同一矩阵展示三个指标可给不同排序 |
| P0 | 最小二乘、约束最小化、Schur 补、白化 | 从目标与约束重新推导补偿，而非背公式 | 解析解与独立线性方程求解交叉核对 |
| P0 | 条件数、前向/后向误差、舍入与消去误差 | 不用小行列式直接判断病态；说明误差在哪一步放大 | 改变尺度/条件数，检查解与残差的变化 |
| P0 | 稳定分解：Cholesky、QR、SVD；阻尼与正则 | 知道何时可求逆、何时应求解；阻尼如何改变目标 | 对奇异或近奇异校准统计设置对照 |
| P1 | 子空间、投影、广义特征值、加权低秩近似 | 区分欧氏最优与任务度量最优 | 比较普通截断 SVD 与加权低秩回归 |
| P1 | 非正规矩阵、谱半径与暂态放大 | 分析循环状态长期误差时不只看单步 MSE | 构造短期小误差、长期放大的状态例子 |
| P1 | 离散格式数值语义 | 明确 ties、饱和、次正规数、尺度精度与归约顺序 | 用边界值验证编码、反量化和矩阵乘 |

现有入口：[数学附录](附录A_推导所需的数学.md)、[GPTQ](02_GPTQ与二阶误差补偿.md)、[FP4 与误差修正](13_新进展_FP4与误差修正.md)。进一步的数值分析可选择 Higham 的 *Accuracy and Stability of Numerical Algorithms*，按条件数、舍入与线性求解主题阅读；作者提供了书籍入口。[Higham 书籍列表](https://nhigham.com/books/)。

### 3.2 优化理论与算法：知道“一个闭式解”到底解决了什么

- [ ] **P0：** 梯度、Hessian、Jacobian、链式法则，及参数空间与输出空间的区别。
- [ ] **P0：** 约束优化、拉格朗日乘子、KKT；必要条件与充分条件。
- [ ] **P0：** 凸性、光滑性、强凸性、条件数与步长；明确哪些部分非凸或离散。
- [ ] **P0：** 坐标下降、交替优化、投影法、近端法；区分精确子问题与启发式更新。
- [ ] **P0：** STE 和 surrogate gradient；检查的是声明的替代反向，不是硬 `round` 的真实导数。
- [ ] **P1：** 信赖域、自然梯度与 Fisher；区分理论 Fisher、经验 Fisher、任务 Hessian和重建 Hessian。
- [ ] **P1：** 流形优化与正交约束，Cayley/QR 类更新及其数值代价。
- [ ] **P1：** 整数规划、背包、动态规划与多目标约束，用于位宽/秩/缓存预算。
- [ ] **P2：** 双层优化、隐式微分、分布鲁棒优化与在线优化，按选题需要深入。

**验收任务：** 对一个量化方法写出“变量、可行域、目标、每步更新、单调性需要的条件、停止规则”。如果更新前后用的不是同一个目标，不能借用坐标下降的收敛论证。推荐用 Boyd 与 Vandenberghe 的 *Convex Optimization* 补齐凸集、对偶、最小二乘与约束基础；该书不能直接替代对非凸量化算法的证明。[作者免费书籍页面](https://web.stanford.edu/~boyd/cvxbook/)。

### 3.3 概率、统计与实验设计：避免把噪声写成贡献

| 优先级 | 知识点 | 在量化研究中的用途 | 必须能解释的边界 |
|---|---|---|---|
| P0 | 期望、方差、协方差、条件概率 | 校准统计、随机旋转、采样与误差传播 | 无偏不等于低方差；相关误差不能按独立噪声平均 |
| P0 | 样本单位与层次结构 | 按题目、文档、会话、训练种子评估 | token 通常不是相互独立的实验样本 |
| P0 | 配对比较、bootstrap、置换检验 | 比较同题两模型、误差条与区间 | 区间方法与重采样单位必须匹配 |
| P0 | 效应大小、置信区间、非劣检验 | 判断小幅退化是否在可接受范围内 | “未显著不同”不证明“等价/无损” |
| P0 | 训练/校准/验证/测试划分，选择偏差 | 阈值、语料、迭代数选择 | 反复查看测试结果调参会污染最终结论 |
| P1 | 因子实验、交互项、匹配预算 | 分开变换、校准、kernel、调度贡献 | 两个加速比不能无条件相乘 |
| P1 | 多重比较、功效与样本量规划 | 多模型、多任务、多超参数搜索 | 不能只报告搜索中最好的一个 p 值或种子 |
| P1 | 分布漂移、域适应、稳健估计 | 校准泛化与长尾任务 | 一种不确定集合不覆盖所有真实漂移 |
| P2 | 集中不等式、随机矩阵、相关采样 | 旋转与随机投影理论 | 结构化随机映射未必满足独立高斯假设 |

**验收任务：** 对同一批任务的两模型结果，报告差值、配对置信区间、分域退化和样本量；再说明该区间是否包含训练/校准随机性。一次模型上的样本 bootstrap，不会自动覆盖重新训练模型的变化。NLP 中检验方法如何依任务和指标选择，可读 Dror 等的 *The Hitchhiker’s Guide to Testing Statistical Significance in Natural Language Processing*。[ACL 论文](https://aclanthology.org/P18-1128/)。

### 3.4 信息论与压缩表示：按真实 bit 而非名字比较

- [ ] **P0：** 标量/向量量化、率失真权衡、固定码本与学习码本、最近邻与 Lloyd-Max。
- [ ] **P0：** payload、尺度、零点、码本、索引、稀疏位置、padding 和未量化张量的总账本。
- [ ] **P0：** 固定长度索引需要向上取整；理论熵、平均编码长度与随机访问成本不同。
- [ ] **P1：** 加法/残差向量量化、乘积码本、trellis、结构化格点与符号平面。
- [ ] **P1：** 编码端自由度与解码格式约束；repack 与重新量化的区别。
- [ ] **P2：** 熵编码、渐进码、变长编码；仅在支持所需随机访问和解码效率时考虑部署价值。

**验收任务：** 在相同完整字节预算下比较两个表示，并解释若码本共享范围、向量轴或解码粒度改变，成本公式需要怎样调整。[现有编码与预算章节](06_码本_稀疏与混合精度.md)。

### 3.5 语言模型本体：量化误差发生在什么计算中

量化研究不能只看线性层矩阵。至少需要掌握：

- [ ] tokenizer、特殊 token、chat template、loss mask 与 attention mask。
- [ ] decoder Transformer 的残差、RMSNorm/LayerNorm、SwiGLU、Q/K/V/O 投影。
- [ ] RoPE 的位置与配对、GQA/MQA、MLA 的缓存对象与投影吸收。
- [ ] prefill/decode、KV 追加、滑动窗口、前缀共享与循环状态。
- [ ] 预训练、SFT、LoRA/QLoRA、蒸馏；知道改了哪些参数和目标。
- [ ] 采样温度、top-k/top-p、EOS、推测解码；固定前缀和自由生成评估的区别。
- [ ] MoE 路由、专家选择/加权、负载分布与低频专家覆盖。
- [ ] 若做多模态：模态编码器、连接器、图像/音频 token 和模态预处理。

**验收任务：** 从一个目标模型配置画出实际量化边界，并在不量化时让手写核心块或分步缓存路径与参考实现相符。进一步可选择 Stanford CS336 的模型构建、数据、系统和训练作业；按目标选做，不要求为每篇量化论文重建整套大模型训练平台。[CS336 2025 课程](https://stanford-cs336.github.io/spring2025/)。

### 3.6 研究软件能力：从“脚本能跑”到“结果可追溯”

- [ ] Python/NumPy/PyTorch 的 tensor shape、stride、view/copy、广播与 dtype。
- [ ] autograd、`detach`、自定义反向、hooks、参数/持久 buffer 与 checkpoint。
- [ ] GPU 内存生命周期、异步执行、设备同步、编译与预热。
- [ ] Git 分支/commit、环境锁定、配置文件、自动检查和失败处理。
- [ ] 随机数与确定性：分开数据抽样、初始化、校准、采样和运行时随机性。
- [ ] 单元测试、性质测试、独立参考实现和有意注入错误的回归测试。
- [ ] 日志与结果结构：run ID、配置、原始测量、异常信息、源码/模型/数据版本。
- [ ] 大规模实验恢复：中断后可重试，但不把不同版本结果混成同一批。

**验收任务：** 用全新目录或另一台机器重跑一个小规模关键实验，自动生成相同定义的结果表；另一个人能依据说明完成复查。依赖版本相同、随机种子固定也不应被写成跨硬件逐位确定性的普遍保证。

### 3.7 把知识依赖转化为研究训练任务

<a id="competency-ladder"></a>

“读过”与“可独立使用”之间至少还有三个层次：能从定义复算，能实现并排错，能识别不适用条件。建议用实际产出来定位能力，而非用阅读时长打分。

| 能力链 | 必做的小产出 | 进阶产出 | 达到研究使用水平的信号 |
|---|---|---|---|
| 线性代数 → 二次优化 → 校准 | 推导一个二阶约束解，核对维度与常数 | 比较欧氏、输入加权、任务加权三个解 | 能解释三个目标何时相同、何时不同 |
| 概率 → 统计估计 → 泛化 | 计算校准统计与配对差值 | 设计跨域/跨种子的确认实验 | 能指出估计器偏差和区间覆盖的随机性 |
| 模型计算图 → 量化变换 → 导出 | 关闭量化验证等价变换 | 打包、保存、重载、差分测试 | 能找到第一次偏离参考的张量或操作 |
| 硬件层次 → kernel → 服务 | 解释一个 GEMM 的搬运与计算 | 画出性能随形状和负载变化的曲线 | 能用测量区分带宽、解码、调度与通信瓶颈 |
| 文献比较 → 假设 → 写作 | 一页最近工作差异表 | 一个可否定自己的最小实验 | 能让他人准确复述新增知识与局限 |

可以采用交错练习：同一周既读关键论文，也实现最小对照，再将观察写成一段精确结论。不要把一年学习和一年研究完全分开；遇到无法解释的实验，才是最具体的补课入口。

### 3.8 如何阅读一篇技术论文的正文、附录与代码

按以下顺序完成一篇“研究级阅读”，而不是只读摘要与结论：

1. **抽取主张。** 作者到底声称改变精度、容量、训练成本，还是执行速度？结论适用于哪些条件？
2. **重写一个目标。** 统一变量方向与量化符号，明确量化参数、数据、权重和梯度中哪些固定。
3. **手推关键步骤。** 只挑承载主要贡献的一两个等式，检查隐藏的近似、尺度、舍入和约束。
4. **跟踪一次数据流。** 输入从哪来，在哪里收集统计、生成码字、存储 scale、加载 kernel、计算任务分数？
5. **检查代码与论文差异。** 默认超参数、后续工程扩展、精度例外和测试配置未必等于论文版本。
6. **独立复现一个关键观察。** 优先选择能验证机制的最小实验，再扩展到报告的模型范围。
7. **写出反对意见。** 最强的替代解释是什么？作者是否通过消融排除了它？还缺哪项证据？

一次阅读的可交付物可以只有一页：一句问题、一个核心式、一个关键实验、一项实现差异、一条可继续调查的限制。比复制整篇论文摘要更容易用于后续选题。

## 4. 按研究方向补齐专项能力

<a id="specialized-knowledge"></a>

### 4.1 算法与校准方向

重点深入：非凸/离散优化、输入加权误差、校准泛化、尺度与码字约束、跨层误差、变换可融合性。

- [ ] 从最终任务问题解释为什么选某个代理目标，而不是先选一个复杂损失再找理由。
- [ ] 与 RTN、相同表示下的强校准方法和最接近新方法比较。
- [ ] 区分“编码更好”与“允许更多尺度/例外/补偿容量”。
- [ ] 给出时间、峰值内存、校准数据和超参数搜索成本。
- [ ] 导出后仍符合声明的目标格式，独立重载得到对应函数。

**建议毕业作品：** 一个保持既有推理格式的校准改进，在隔离任务上有可重复收益，并解释它改善哪类误差、何时无效。现有的[优化量化器](04_可学习校准与HQQ.md)和[鲁棒/尺度修正](13_新进展_FP4与误差修正.md)是起点。

### 4.2 内核与推理系统方向

重点深入：CUDA 执行层次、SIMT、warp、合并访存、shared memory、寄存器、occupancy、bank conflict、Tensor Core、tile、流水线、异步拷贝、归约及 roofline。

- [ ] 能区分访存带宽、解码吞吐、计算吞吐、launch 和同步等瓶颈。
- [ ] 能写或修改一个带真实低比特 payload 的 GEMM/Attention 内核，并用独立高精度参考验证。
- [ ] 理解 Triton 与 CUDA 的抽象层次；性能需要进一步核查编译后的执行路径。
- [ ] 理解图编译、动态形状、CUDA Graph、预打包与 autotuning 的冷启动/稳态成本。
- [ ] 做服务时补齐连续批处理、chunked prefill、KV 分页、负载与排队。
- [ ] 做多 GPU 时补齐 tensor/expert/pipeline parallel、collective、拓扑与通信重叠。
- [ ] 把微基准收益放回完整模型与服务场景，不能只报最适合的一个 M/N/K。

Triton 官方教程提供从基础算子到矩阵乘等实例，CUTLASS 说明 GEMM 的分块与流水线层次；Nsight Compute 文档用于理解测量与 replay 的边界。先掌握目标硬件，再追求特定新指令。[Triton 教程](https://triton-lang.org/main/getting-started/tutorials/index.html)、[CUTLASS GEMM](https://docs.nvidia.com/cutlass/latest/media/docs/cpp/efficient_gemm.html)、[Nsight Compute Profiling Guide](https://docs.nvidia.com/nsight-compute/ProfilingGuide/index.html)。

### 4.3 低比特训练与恢复方向

重点深入：优化器状态、混合精度、梯度缩放、量化反向、checkpointing、蒸馏目标、on-policy/off-policy 数据，以及训练预算分配。

- [ ] 区分 QAT 模拟和真实低精度前向/反向计算。
- [ ] 检查梯度是否与声明的替代计算图一致，特别是量化概率和重算 Attention。
- [ ] 区分固定前缀梯度与前缀分布随模型变化带来的梯度项。
- [ ] 对训练稳定性报告发散、溢出、loss spike、梯度统计和恢复策略。
- [ ] 比较全部训练 token、模型规模、教师调用、FLOPs 与设备时间，而非只比较最后适配步数。
- [ ] 检查 adapter 合并、再次量化和保存重载后的模型质量。

**建议毕业作品：** 固定基础 checkpoint 和恢复预算，证明某个梯度/数据策略改善低位宽恢复，且部署后收益保留。尚未具备稳定训练资源时，先做已有模型的恢复研究，比直接开展原生低比特大规模预训练更可控。[训练章节](07_QAT_QLoRA与原生低比特.md)、[训练与 MoE 进展](14_新进展_训练与MoE.md)。

### 4.4 KV、长推理与循环状态方向

重点深入：softmax 敏感性、K/V 不同误差路径、RoPE、缓存生命周期、动态范围、分段归约、状态空间与误差反馈。

- [ ] 区分普通 K/V、MLA 内容潜变量/位置分支与循环状态，按实际对象算容量。
- [ ] 对比量化写入时机、最近窗口、sink、页边界与共享前缀。
- [ ] 分开固定前缀局部误差和自由生成长轨迹退化。
- [ ] 如果动态提升精度，说明高精度信息来自副本、残差还是重算。
- [ ] 对长度、位置和任务难度做分桶，避免只用短 PPL 代替长上下文能力。
- [ ] 缓存能装更多 token，不自动说明模型能可靠利用更长上下文。

**建议毕业作品：** 对一个明确架构和预算，提出缓存误差或信息保留策略，完成状态正确性、长任务质量与缓存读写开销验证。[KV 基础](08_KV缓存与Attention量化.md)、[KV 与状态进展](15_新进展_KV与推理系统.md)。

### 4.5 MoE 与结构联合压缩方向

重点深入：gate/top-k、专家覆盖、共享谱基、结构化剪枝、低秩与量化的耦合、离散资源分配、grouped GEMM 与专家通信。

- [ ] 总参数、每 token 激活参数、每设备驻留参数分别统计。
- [ ] 直接测量专家扰动影响，不把激活频率自动当作敏感性真值。
- [ ] 处理共享部分的相关误差，不能假定专家误差独立后平均掉。
- [ ] 比较 router 固定/量化、共享基精度、专家因子精度的分离消融。
- [ ] 检查低频任务和专家，不只报告全体平均质量。
- [ ] 稀疏、低秩和位宽收益必须在相同完整容量或实际服务约束下比较。

### 4.6 理论或经验分析方向

理论主线额外补：随机矩阵、集中界、率失真、矩阵扰动、在线稳定性、非凸优化；经验主线额外补：测量误差、因果识别思路、配对设计、分层统计和基准构建。

**共同要求：** 结论应带来可用的新认识。例如揭示某个被广泛使用的代理在什么条件下反转排序，并给出可执行的诊断或修复。单个刻意构造的玩具反例可以启发研究；若要宣称真实 LLM 的普遍问题，仍需对应真实证据。

### 4.7 多模态、检索与工具使用：扩大对象，同时保持归因清楚

量化研究的边界可从纯文本生成扩展到多模态模型、embedding/retriever、reranker 和工具调用，但每个方向都需要自己的质量定义。

| 对象 | 额外需要的知识 | 关键测量 | 容易误判的地方 |
|---|---|---|---|
| 视觉/音频语言模型 | 模态预处理、编码器、连接器、跨模态 token 与注意力 | 分组件量化，视觉/音频条件任务、长度与模态比例分层 | 文本 PPL 正常不代表模态信息保持 |
| embedding / retriever | 相似度、归一化、召回排序与索引 | 固定语料/索引的召回、排序、向量误差与延迟 | 编码向量范数或角度改变可能影响排名，语言生成指标不适用 |
| reranker / RAG | 候选集、排序损失、上下文拼接与生成归因 | 固定候选看排序，固定证据看生成，再测全链路 | 检索随机变化会掩盖生成量化的贡献 |
| 工具与结构化输出 | schema、解析、调用执行、错误恢复 | 内容正确、参数正确、格式、执行成功和重试成本 | JSON 可解析不等于调用语义正确 |
| 长上下文推理 | 信息位置、多跳依赖、聚合和干扰强度 | 长度×位置×任务复杂度，而非只有检索一根针 | 一种简单 needle 测试不能代表完整上下文理解 |

RULER 的设计将长上下文测试从简单检索扩展到多跳追踪与聚合等任务，适合参考如何构造多个能力维度；它仍是有特定任务构造的 benchmark，不能代表所有真实长任务。[RULER 原论文](https://arxiv.org/abs/2404.06654)。

扩展方向时先做分组件对照。例如在 RAG 中固定同一检索结果，只改变生成模型量化；再独立评估检索模型压缩；最后检查组合。否则“整体准确率变差”无法定位到具体量化对象。

### 4.8 故障诊断、可解释性与因果证据

量化误差热图、离群值比例、通道频率或谱能量可以发现相关现象，但**相关统计不是敏感性的真值**。需要把观察转化为干预：

- 恢复一层或一组高精度，观察任务变化；再用同成本随机恢复作对照。
- 在固定位置注入方向受控、范数匹配的扰动，检查理论预测。
- 保持位宽和容量不变，仅调整码字/尺度或变量所在坐标系。
- 对共享模块检查全部消费者，对路由检查选择边界及 gate 变化。

单层恢复后收益大，不必然意味着该层独立“最重要”：上游误差、下游放大与层间交互都可能改变恢复效果。局部干预通常回答该状态下的因果问题，跨层分配仍需联合确认。

## 5. 如何找到值得做且确有空间的问题

<a id="problem-selection"></a>

### 5.1 建立“最近工作”对照，而不只是论文列表

针对一个细分问题，先精读若干最接近工作及其关键前驱。可以从 8–15 篇的工作集开始，数量只是整理建议；如果关键文献不在其中，读够数量也不能证明覆盖充分。

每篇都填写：

| 维度 | 具体内容 |
|---|---|
| 身份 | 标题、作者、首次公开日期、会议与版本；同名方法用论文标识区分 |
| 对象 | W/A/KV、MLA、状态、router、训练梯度或系统路径 |
| 目标 | 精度、平均重建、最坏误差、吞吐、延迟、成功任务成本 |
| 自由度 | 优化码字、尺度、变换、位宽、秩、数据或调度中的哪些变量 |
| 约束 | 格式、完整 bit、硬件、模型架构、训练/校准预算 |
| 证据 | 理论假设、模型/任务范围、基线版本、重复、失败案例 |
| 限制 | 作者明确的局限，以及自己能复现的缺口 |
| 关系 | 与候选想法等价、包含、互补，还是实质不同 |

检索时同时使用方法名、问题描述、目标函数、格式/硬件关键词，并追踪引用与被引用工作、作者仓库、OpenReview 讨论及官方实现。**没有搜到同名方法不等于没有等价思路。** 选题开始、核心结果出现、投稿前分别更新一次；这是新颖性尽职核查，不能绝对证明“全世界无人做过”。

#### 已填写的对照：固定权重格式下的校准泛化

<a id="calibration-evidence-comparison"></a>

**本轮聚焦问题：** 对同一个 checkpoint、同一 W4A16 分组格式和执行后端，改变校准数据或重建目标，能否改善独立任务质量？
下表于 2026-10-20 对照指定版本的实验段落填写。GPTQ/AWQ 是基线，LeanQuant 改变量化网格，DRQ 在网格固定后修改整数码；后两者的干预位置不同。
这是一个已展开的工作集，尚不能作为新颖性已确认的结论；确定选题后仍须补查 GPTAQ、OmniQuant、AutoRound 等最接近方法。

| 方法与版本 | 改变的变量 | 原文模型、任务与表示范围 | 校准与位宽口径 |
|---|---|---|---|
| [GPTQ v2，§5](https://arxiv.org/html/2210.17323v2) | 逐列码字与未量化权重补偿 | OPT/BLOOM，多规模语言建模与零样本任务；主要 W3/W4 weight-only | C4 128×2048 token；主结果采用逐行仿射网格。W4 标签不含全部元数据，不能当作 W4-g128 完整格式 |
| [AWQ v6，§5.1、§5.3](https://arxiv.org/html/2306.00978v6) | 通道缩放及裁剪搜索 | LLaMA/OPT 等；泛化实验为 OPT-6.7B INT3-g128，PubMed/Enron 交叉校准与评测 | Pile 校准、20 个缩放候选；数据量实验比较 16 与 192 条序列。该段未给完整有效 token/字节账本，不能直接换算成本 |
| [LeanQuant v3，§4、表 9](https://arxiv.org/html/2407.10032v3) | 损失加权网格拟合，再做二阶补偿 | Llama/Mistral；表 9 单列仿射 W4-g128 与 AWQ/OmniQuant；另有非均匀码本路线 | C4 128×2048 token，默认 p=4；表 9 报 4.25 bit/weight，仍需核对未量化张量和实际打包；非均匀格式不能混入同格式对照 |
| [DRQ v1，§4.1、附录 C](https://arxiv.org/html/2610.11226v1) | 固定尺度、零点、分组和算子，只更新整数码 | Llama-Instruct 1B/3B/8B/70B、Qwen3-30B-A3B；WT2/C4 PPL 与七项任务；W2/W3/W4-g128 | WT2 train 128×2048 token，另用 Pile 64 个验证样本选参数；每层搜索 512 个激活向量、两组各 256 个检查向量。增量参数为零不等于完整模型恰为标称位宽 |

| 原文中的具体对照 | 结果能支持什么 | 成本与失败边界 |

### 5.2 从稳定现象形成可证伪假设

一个合格的问题应包含：

> 在模型/格式/工作负载 C 下，现有方法 A 出现限制 L。我们推测机制 M 导致该限制；如果 M 成立，则干预 I 应改变可观测量 O，并在完整预算 B 下改善指标 Y。若结果 F 出现，就放弃或缩小该假设。

例子：**以下是问题结构示例，不是已确认创新。**

> 在同一 W4 部署格式下，通用校准集上的层 MSE 无法预测代码任务退化；假设少量任务敏感方向被平均误差掩盖。先验证方向扰动与实际退化的关系，再比较同校准预算的定向目标和强基线。若换到隔离代码任务无收益，则不保留“泛化改善”的主张。

### 5.3 判断一个想法是否值得进入大实验

- [ ] 问题对目标场景具有实际后果，而不仅是一个容易改的参数。
- [ ] 能明确指出与最近工作的区别，且区别会改变某项可检验行为。
- [ ] 已有可重复观察，或有足够清晰的理论动机。
- [ ] 一个小实验就能排除主要错误解释。
- [ ] 至少一个强基线能在相同条件下稳定运行。
- [ ] 新方法能导出到可执行格式，或有能力完成所需后端。
- [ ] 总算力能覆盖失败、重跑、消融与最终独立验证。
- [ ] 即使结果为否定，也能形成关于机制或适用条件的有用认识。

**停止或转向信号：** 最近工作已覆盖相同机制和条件；收益完全由更多参数/训练/校准预算解释；只有在一个被反复挑选的样本上获益；实现关键部分在现有资源下无法验证；效果小于测量和随机波动且没有机制价值。停止一个假设是研究进展，不必为了保留方法名称继续扩大投入。

### 5.4 用“改变了哪一项”检查新颖性

<a id="novelty-audit"></a>

将最近工作与自己的方案写成同一表示：

$$
\min_{\phi\in\mathcal F}\;\mathbb E_{x\sim\mathcal D}\bigl[\ell(f(x),f_{Q,\phi}(x))\bigr]
\quad\text{subject to}\quad M(\phi)\le B_M,\;T(\phi)\le B_T.
$$

然后逐项询问：变化来自数据分布 $\mathcal D$、损失 $\ell$、优化变量 $\phi$、可行域 $\mathcal F$，还是成本函数和执行方式？

| 自己声称的差异 | 必须进一步检查 | 可能形成的贡献 |
|---|---|---|
| 新的权重系数或尺度 | 是否只是变量替换、已有加权最小二乘或正则的另一写法 | 新敏感性来源、可行性约束或更可靠的估计 |
| 两种方法组合 | 两者是否本就可交换/可直接串联，收益是否来自预算增加 | 解决原先不能兼容的条件，解释并利用交互 |
| 新硬件格式 | 是否只替换dtype，原方法是否已经能直接导出 | 处理该格式特有尺度、布局、累加或编码约束 |
| 新模型/任务 | 结构或分布是否带来旧方法无法处理的真实问题 | 揭示新的失效机制并提供相应解决或诊断 |
| 更快实现 | 速度是否来自更弱精度、不同shape或少算工作 | 数值等价或同质量下的新执行设计 |
| 新评测 | 是否只是新增任务数量，还是测到了此前遗漏的能力 | 可重复的新规律、能改变决策的测量方法 |

创新不必意味着所有组成部分都新，但必须清楚说明**新增知识在哪里，以及旧知识为什么不足以得到同一结果**。若只是已有问题换符号，不应靠增加复杂术语掩盖。

### 5.5 以信息价值选择下一项实验

研究预算有限时，下一项实验应优先区分最关键的两个解释。可以按以下顺序决策：

1. 如果“实现有误”仍是合理解释，先做正确性检查；不要直接扩大模型。
2. 如果“多用了容量/数据/时间”能解释优势，先做同预算对照。
3. 如果现象只在一次运行出现，先检查重复与测量波动。
4. 如果机制明确但范围未知，再做跨模型、跨域或跨shape验证。
5. 如果质量已经达标但速度没有，先 profile 并检查成本分解，再设计更复杂算法。

有时一个两小时的负对照，比再跑一周排行榜更能决定方向。高成本实验应承担明确的决策作用，例如“若在第二个模型家族仍无信号，就停止通用性路线”，而不只是让表格多一行。

### 5.6 维护问题树和反证树

将核心现象拆成可检验分支。例如“W4 后代码能力下降”可以有以下解释：格式/解析错误、校准域偏差、少数敏感层、长轨迹放大、解码策略变化。每个分支都应有一个能支持它的观察和一个能推翻它的实验。

不要把第一次最符合直觉的解释直接写成方法动机。研究中途若主解释被否定，应更新问题树，保留有依据的发现，并重新评估贡献类型：可能从新算法转为误差机制或测量方法研究。

### 6.3 实现按四层推进

1. **明确的数学参考实现**：小维度、高精度、可检查每个中间量；优先正确。
2. **格式参考实现**：真实码字、尺度、打包、padding 与保存重载；确认不会靠隐藏高精度副本获得精度。
3. **高效实现**：融合、布局、kernel、并行；对参考实现做差分检查。
4. **模型与服务集成**：完整模型质量、内存、阶段计时和实际负载。

算法论文可以使用已有高效后端，但必须证明导出的格式和该后端一致。系统论文则需要完成其核心执行路径，不能以 Python QDQ 代替低比特硬件实现。理论论文不必都拥有服务平台，但不能写超出验证范围的部署速度结论。

### 6.4 三种特别值得做的对照

**等价变换对照：** 关闭量化时原模型与变换后模型应在声明数值容限内一致，否则后续效果无法归因于量化。

**理想化对照：** 暂时使用高精度残差或更充分的搜索，观察去除某类表示约束后能改善多少对应重建目标，再恢复实际低精度格式。只有明确的可行集合包含关系与相同目标下的最优求解，才能严格称为界；高精度残差并不自动给出任务准确率的数学上界，理想化结果也不能当部署成绩。

**反事实对照：** 随机选择重要通道、随机分配相同精度预算、使用同预算的简单启发式。如果精心设计的策略未优于这些对照，复杂机制可能没有提供被声称的信息。

### 6.5 一条研究主线：从权重误差推到任务误差

<a id="error-geometry"></a>

设单个线性层的输入行向量为 $x\in\mathbb R^{1\times d}$，权重 $W\in\mathbb R^{m\times d}$，固定量化误差 $E=\widehat W-W$。局部输出误差为 $\delta y=xE^T$。在给定输入分布上，假设二阶矩存在，定义**未中心化二阶矩** $C=\mathbb E[x^Tx]$，则有精确等式

$$
\mathbb E\|\delta y\|_2^2
=\operatorname{tr}(ECE^T).
$$

普通权重 MSE 对应各输入方向等权；只有 $C$ 与单位阵成比例等特殊条件下，它才与输出重建目标仅差常数。GPTQ 的线性重建目标可从这条关系理解，但这仍不是整个模型最终任务损失。[GPTQ 原论文](https://arxiv.org/html/2210.17323v2)。

假设该层输出之后的网络为 $g$，输出 logits 为 $z=g(y)$。把列向量形式的局部误差记为 $\delta y^T$，小扰动下

$$
\delta z^T\approx J_g(y)\delta y^T.
$$

对固定教师分布 $p=\operatorname{softmax}(z)$，用量化分布 $q=\operatorname{softmax}(z+\delta z)$ 近似它，局部 KL 展开为

$$
D_{KL}(p\|q)
=\frac12\delta z\,F_z\,\delta z^T+O(\|\delta z\|^3),
\qquad F_z=\operatorname{diag}(p)-p^Tp.
$$

这里 $p$ 按行向量书写，$p^Tp$ 是词表维度的外积。展开来自 $D_{KL}(p\|q)=\operatorname{LSE}(z+\delta z)-\operatorname{LSE}(z)-p\delta z^T$，其中 $\operatorname{LSE}(z)=\log\sum_i e^{z_i}$；一阶项相消，二阶导即 $F_z$。因此任务概率失真对应的局部度量包含 $J_g^TF_zJ_g$，与单纯的 $C$ 或单位阵不同。该展开只在固定教师、相同前缀、有限 logits 和足够小扰动附近成立；它不证明自由生成行为已保持。

**一个值得研究的结构：** 如果论文优化 $\mathbb E\|xE^T\|^2$，但业务关心最终 token 分布、路由或执行成功率，就存在代理目标与任务目标之间的距离。研究可以来自更好的输出度量、更可靠的估计或更便宜的近似，而不一定需要再发明一种低比特格式。

#### softmax 的不变方向解释了为何 logit MSE 不总合适

给所有 logits 加相同常数不改变 softmax。因为 $F_z\mathbf1=0$，上面的 KL 二次型也不惩罚这个方向；普通 logit MSE 却会把它计为误差。反过来，相同大小的相对 logit 扰动在决策边界附近可能更重要。

下面用独立的精确 softmax 和 KL 核对局部二次式，同时验证线性输出误差的迹形式：

```python
import numpy as np

X = np.array([[1., 2.], [-1., 1.], [2., 0.]])
E = np.array([[.1, -.2], [.05, .3]])
C = X.T @ X / len(X)
output_risk = np.mean(np.sum((X @ E.T)**2, axis=1))
assert np.isclose(output_risk, np.trace(E @ C @ E.T))

z = np.array([1.2, -.4, .3])
def softmax(v):
    e = np.exp(v-v.max())
    return e/e.sum()
p = softmax(z)
F = np.diag(p)-np.outer(p, p)
assert np.allclose(F @ np.ones(3), 0.)
assert np.allclose(softmax(z+7.), p)

direction = np.array([.2, -.1, .4])
ratios = []
for eps in (1e-2, 1e-3):
    delta = eps*direction
    q = softmax(z+delta)
    exact = np.sum(p*(np.log(p)-np.log(q)))
    quadratic = .5*delta @ F @ delta
    ratios.append(exact/quadratic)
assert abs(ratios[-1]-1) < 1e-3
print('output risk:', output_risk, 'KL/quadratic:', ratios)
```

这段程序是机制验证，不是新量化方法，也没有测模型质量或速度。向量维数、扰动幅度和模型状态变大后，应重新检查近似残差。

### 6.6 分清四种“二阶信息”及其估计成本

<a id="curvature-estimation"></a>

| 对象 | 数学含义 | 容易混淆的地方 |
|---|---|---|
| 线性重建 Hessian | 对 $\|X(\widehat w-w)\|^2$ 求导得到 $2X^TX$ | 它对该二次重建目标精确，不是整个模型任务 Hessian |
| 任务 Hessian | 下游损失关于参数的二阶导 | 非凸模型下未必半正定；不能随意作为距离度量 |
| 模型 Fisher | 依模型分布对 score 外积取期望 | 期望的标签分布、模型与正则条件必须写清楚 |
| 经验梯度外积 | 用实际样本/标签的梯度平方或外积平均 | 不自动等于模型 Fisher、Hessian 或其可靠近似 |

例如 Bernoulli 模型以 logit $\theta$ 参数化，$p=\sigma(\theta)$。对标签 $y$ 的负对数似然，梯度为 $p-y$、Hessian 为 $p(1-p)$。模型 Fisher 也为 $p(1-p)$，但**单个实际标签**的经验梯度平方是 $(p-y)^2$。当 $p=0.9,y=1$ 时，后者为 0.01，前两者为 0.09。只有明确的分布平均与条件才能建立更强关系。

自然梯度、广义 Gauss–Newton 与 Fisher 的联系可读 Martens；经验 Fisher 的适用性问题可读 Kunstner 等。本文借此说明估计对象需要区分，不把任一梯度平方统计一概判为无用。[Martens：New Insights and Perspectives on the Natural Gradient Method](https://jmlr.org/papers/v21/17-678.html)、[Limitations of the Empirical Fisher Approximation](https://arxiv.org/abs/1905.12558)。

#### 平均梯度的平方不等于梯度平方的平均

若每样本梯度为 $g_i$，经验二阶统计使用 $\frac1n\sum_i g_i g_i^T$；先对 batch 求平均再外积，得到的是 $\bar g\bar g^T$。两者差一个梯度协方差项。特别地，$g_1=1,g_2=-1$ 时前者为 1，后者为 0。

因此用普通 batch backward 收集“Fisher 对角”时，必须说明：梯度是逐样本、逐 token、逐序列还是整批聚合？loss 用 sum 还是 mean？不同 batch 与序列长度会改变权重。一个名叫 `fisher` 的变量不能替代这些定义。

#### 校准统计本身也是一个估计问题

有限样本给出 $\widehat C=X^TX/n$，其秩至多为 $\min(n,d)$。长文档内 token 相关，增加 token 数不等于增加同样多的独立信息。若目标分布二阶矩为 $C_*$，对给定误差矩阵 $E$，有

$$
R_*(E)-\widehat R(E)
=\operatorname{tr}[E(C_*-\widehat C)E^T],
$$

$$
|R_*(E)-\widehat R(E)|
\le\|C_*-\widehat C\|_2\,\|E\|_F^2.
$$

第二式由矩阵谱范数与 PSD 权重的迹界得到。它清楚区分“给定统计下优化量化器”与“统计是否代表目标分布”。但 $C_*$ 在实际中未知；若 $E$ 还根据同一数据自适应选择，也不能只写这个确定性不等式就宣称已证明泛化，需要控制统计估计与选择过程。

可研究的改进包括分域采样、低频激活覆盖、对角/块近似、收缩估计、低秩加对角或 sketch。应比较其偏差、方差、内存和下游质量；更精细的非对角估计可能同时引入更多样本噪声。

收缩示例为

$$
\widetilde C=(1-\lambda)\widehat C+\lambda\tau I,
\qquad \tau=\operatorname{tr}(\widehat C)/d.
$$

这里 $0\le\lambda\le1$；若 $\tau>0$ 且 $\lambda>0$，该式给出正定矩阵。全零统计时 $\tau=0$，不能靠此式自动消除奇异性，还需显式的有效下限或退化分支。$\lambda$ 应在开发数据或明确的统计准则下选择；该变换改变了目标度量。一般坐标变换下，单位阵正则也不自动保持不变，因此必须说明估计在什么坐标系进行。

### 6.7 多层与长轨迹：误差为什么会相互抵消或放大

<a id="error-propagation"></a>

将隐状态暂按列向量书写，原网络为 $h_{l+1}=f_l(h_l)$，量化路径为 $\widehat h_{l+1}=\widehat f_l(\widehat h_l)$。定义 $e_l=\widehat h_l-h_l$，并令 $r_l=\widehat f_l(\widehat h_l)-f_l(\widehat h_l)$，即在同一实际输入状态下比较两种局部实现。只对浮点映射 $f_l$ 在 $h_l$ 附近做一阶展开，可写成

$$
e_{l+1}\approx J_l e_l+r_l,\qquad
J_l=\frac{\partial f_l}{\partial h_l}.
$$

若初始误差为零，则最终误差近似为

$$
e_L\approx\sum_{l=0}^{L-1}
\left(\prod_{j=l+1}^{L-1}J_j\right)r_l,
$$

其中乘积为 $J_{L-1}\cdots J_{l+1}$，较大索引在左，空乘积为单位阵；这描述扰动向后续层传播。$r_l$ 本身仍可依赖实际状态与量化网格，所以该式不是独立噪声模型。最终平方误差包含不同层贡献的交叉项。因此“把各层 MSE 相加”或“单独恢复一层时收益最大就一定应给它更多 bit”都需要额外近似与联合确认。

在自回归生成中，还存在另一层反馈：量化改变了早期 token，后续输入前缀分布也随之改变。固定教师前缀评估与学生自由生成回答不同问题。序列预测中训练分布和自身行为诱导分布不一致的问题，在模仿学习研究中已有明确讨论；可借鉴其问题分析，但不能直接继承其定理为 LLM 量化保证。[Ross 等：A Reduction of Imitation Learning and Structured Prediction to No-Regret Online Learning](https://proceedings.mlr.press/v15/ross11a.html)。

**建议用三组实验分离误差：**

1. 同一固定前缀比较 logits，测局部模型差异。
2. 记录浮点/量化模型各自产生的前缀，再交叉回放到两模型上，观察状态分布变化。
3. 用固定任务与生成预算比较最终成功、长度、EOS、工具调用和恢复成本。

第二组的交叉回放是诊断，不自动得到真实策略替换后的因果效果；生成策略、温度和支持范围也需固定。

### 6.8 理论结果应附带“它解决了哪一层问题”

一个定理可以解决固定码字的最优尺度、固定误差矩阵的最坏分布、固定网格的局部补偿或某个随机模型的期望误差。它未必解决整个量化模型的全局搜索和业务任务质量。

写证明时建议把五件事并排放置：**变量与可行域、结论、关键假设、证明依赖、算法实际满足情况**。尤其检查：

- 证明针对无限网格还是有限饱和网格？物理尺度是否也量化？
- 随机性来自输入、量化器、旋转还是抽样？是否满足独立条件？
- 结论是期望、概率上界、确定性界还是存在性？
- 误差对象是权重、层输出、logits、概率还是最终任务？
- 用于证明的最优子程序是否可计算，实际近似解还保留什么性质？
- 给出的界是否紧到足以区分方法，还是仅保证一个很宽的上限？

例如证明“给定误差矩阵时最坏方向由最大特征向量达到”不等于证明“更新码字后鲁棒目标一定降低”；因为更新也改变了最坏方向。将这类层次写清楚，通常比堆砌不适用的收敛符号更有价值。

### 6.9 一个统一的研究决策目标，以及它的局限

可以将部署配置 $\pi$ 看作位宽、尺度、例外、变换、补偿、kernel 与调度的组合：

$$
\min_{\pi\in\Pi}\;C_{deploy}(\pi)
\quad\text{subject to}\quad
Q_j(\pi)\ge q_j^{min}\;\forall j,\quad
M_{peak}(\pi)\le B_M,\quad
T_{p95}(\pi)\le B_T.
$$

质量指标按“越大越好”统一记号；PPL 等方向相反的指标需要相应改写。该式是研究目标的组织方式，不是已知可精确求解的优化算法。

若改用单一加权目标 $L+\lambda M+\mu T$，不同系数会选不同折中；离散、非凸可行集里，简单权重扫描也未必找到全部 Pareto 最优点。对于必须满足的质量或延迟门槛，应直接报告约束是否满足，而不只给一个不透明的综合分数。

"""科研进阶：隔离测试、同格式校准搜索与配对bootstrap，完成一个小型研究闭环。"""
import torch
from experiments.demo_runtime import get_runtime

# 第 0 步：auto优先CUDA；runner可用--device指定。所有计算张量在此设备创建。
rt = get_runtime()
device, dtype = rt.device, rt.dtype

# 第 1 步：先固定数据划分与候选，再看结果；三个集合不会复用同一行输入。
rng = rt.rng(2026)
W = rng.normal(size=(4, 8))
# 人为放大一个权重通道、却让校准集很少激活它，构造可解释的分布错配。
W[:, 0] *= 8
calibration = rng.normal(size=(48, 8))
development = rng.normal(size=(48, 8))
test = rng.normal(size=(128, 8))
calibration[:, 0] *= .01
development[:, 0] *= 2
test[:, 0] *= 2
base_scale = torch.amax(abs(W), dim=1, keepdim=True)/7
candidates = (.5, .75, 1., 1.25, 1.5)

# 第 2 步：所有候选都保存同样的4-bit整数码和每行FP16尺度，固定格式预算。
# 这里搜索统一裁剪倍率，不是DRQ或任何新算法；用于练习研究协议。
models = []
for factor in candidates:
    scales = (base_scale*factor).to(torch.float16)
    codes = torch.clamp(torch.round(W/scales.to(dtype)), -7, 7).to(torch.int8)
    decoded = codes*scales.to(dtype)
    # 将两种数据上的误差分别记录，不能让test决定候选。
    cal_loss = torch.mean((calibration@(decoded-W).T)**2)
    dev_loss = torch.mean((development@(decoded-W).T)**2)
    models.append((decoded, float(cal_loss), float(dev_loss)))
cal_best = min(range(len(models)), key=lambda i: models[i][1])
dev_best = min(range(len(models)), key=lambda i: models[i][2])
baseline = cal_best  # 对照“校准集选参”与“目标域开发集选参”，两者候选数量相同。
print('候选 / 校准MSE / 开发MSE:', [(f, m[1], m[2]) for f, m in zip(candidates, models)])
print('校准选择 / 开发选择的倍率:', candidates[cal_best], candidates[dev_best])
assert cal_best != dev_best  # 只验证这个预设分布错配例子，不作为一般保证。

# 第 3 步：选择冻结后才读取test；每行一个独立样本，保留逐样本差值。
base_errors = torch.mean((test@(models[baseline][0]-W).T)**2, dim=1)
chosen_errors = torch.mean((test@(models[dev_best][0]-W).T)**2, dim=1)
differences = chosen_errors-base_errors  # 负值代表这个MSE目标改善。

# 第 4 步：bootstrap保持同一输入上的基线/候选配对；只估计当前模型的样本波动。
resampling = rt.rng(2027).integers(0, len(test), size=(5000, len(test)))
interval = torch.quantile(differences[resampling].mean(dim=1), rt.tensor([.025, .975]))
assert models[dev_best][2] <= models[baseline][2]
assert torch.isfinite(interval).all()
print('独立测试平均MSE差 / 95%百分位区间:', differences.mean(), interval)

# 第 5 步：有限证据只对应此小模型的层误差，不支持真实LLM任务结论。
print('证据范围：合成线性层、同格式、开发集选参；未测生成质量或GPU速度。')

## 7. 可信实验的详细清单

<a id="experiment-design"></a>

### 7.1 先写协议，再跑大规模搜索

开始前用配置文件或研究计划明确：主假设、主要指标、允许的质量下降、数据划分、基线、预算、统计方法和失败处理。它可以随探索修改，但要区分探索阶段与冻结后的确认阶段；已经看过并用于调参的测试集不能继续作为未见测试证据。

### 7.2 基线必须足够强且可比

- [ ] 有同轮浮点基线，固定 checkpoint、tokenizer、模板、推理/评测设置。
- [ ] 有简单基线，如同格式 RTN、固定窗口或统一位宽。
- [ ] 有最接近的强基线，以及与贡献最相关的近期工作。
- [ ] 优先使用作者实现或可信官方实现，固定 commit；改动必须可说明。
- [ ] 核对基线的排除层、组大小、尺度精度、校准数据、误差补偿与内核。
- [ ] 给基线合理调参预算，不能只精调新方法、基线全部用不合适默认值。
- [ ] 若基线复现明显差于报告值，先解释协议或版本差异，再使用它支持优势结论。
- [ ] 不支持目标格式的基线可以单列，不能静默换成更弱方法。

**区分两种公平性：** 算法机制比较尽量固定模型、表示、数据与搜索预算；部署选型固定质量门槛、资源和请求分布，允许各方法使用合法的最佳配置，但需披露差异。两种实验都可做，不能把后一种的整体收益全部归因于一个算法步骤。

### 7.3 建立分阶段实验矩阵

下表是控制算力的建议，不是任何会议的最低数量要求。

| 阶段 | 模型与数据 | 比较范围 | 进入下一阶段的条件 |
|---|---|---|---|
| 排错 | 小矩阵、短样本、一个小模型 | 数值/布局/梯度/缓存边界 | 独立参考与实现相符 |
| 发现 | 一个目标模型，一组校准/验证数据 | 强基线与少量候选 | 有可解释、可重复的信号 |
| 确认 | 未用于选方法的任务/数据，必要时独立校准抽样 | 冻结配置与主要基线 | 主效应超过合理不确定性或揭示明确边界 |
| 泛化 | 与主张相关的其他模型家族、规模、任务或长度 | 关键候选与强基线 | 能界定适用范围，而非只展示一个成功点 |
| 部署 | 目标设备、真实后端、代表性形状和负载 | 完整链路与成本 | 在质量约束下兑现收益 |

若论文声称跨架构通用，建议至少考虑多个模型家族和规模；若只解决某个架构的真实限制，可以收窄主张，但需把该场景论证充分。没有一个“测够两个模型就合格”的通用规则。

### 7.4 量化配置必须完整

- [ ] W/A/KV/梯度/状态各自位宽和格式，不只写 W4。
- [ ] 对称/仿射/浮点 offset，编码区间与半格舍入规则。
- [ ] per-channel/per-group 的具体轴、组大小与尾部处理。
- [ ] scale、zero point、码本的存储精度；嵌套量化和全局尺度。
- [ ] 异常权重/激活、未量化层、router、embedding、输出头与共享关系。
- [ ] 在线/离线旋转，缩放、补偿分支、残差、秩和需要的临时变量。
- [ ] 存储格式、打包布局、实际 kernel、累加与输出精度。
- [ ] GPTQ 类配置中的计算分块、量化分组、排序与逐模块校准顺序。
- [ ] KV 的写入时机、RoPE 前后位置、窗口、分页、共享和回退。
- [ ] 训练时哪些参数可更新，哪些状态保留高精度。

### 7.5 校准数据与评估数据

- [ ] 同时记录样本条数、实际有效 token、长度分布、语言/领域比例。
- [ ] 说明文档拼接、截断方向、特殊 token、padding 过滤和模板处理。
- [ ] 明确校准统计来自浮点输入，还是来自已量化前层/学生轨迹。
- [ ] 对数据选择算法计入选择本身的教师调用和搜索成本。
- [ ] 对比等 token、等时间或等总校准成本，说明自己采用哪一种公平口径。
- [ ] 校准、验证和最终测试按文档/来源等合适单元隔离，检查近重复。
- [ ] 目标任务是长代码或长推理时，不能仅以短通用文本代表。
- [ ] 无数据方法也需要独立质量评估；“不校准”不意味着“输入分布无关”。

### 7.6 质量指标：由主张选择，不是越多越好

| 层次 | 建议指标 | 注意事项 |
|---|---|---|
| 张量 | MSE/NMSE、最大误差、范数/方向、裁剪率 | 统一归一化与参考；不等于任务质量 |
| 层/块 | 输出误差、敏感方向、路由变化 | 使用相同输入；区分上游误差 |
| 概率 | NLL/PPL、明确方向的 KL、logit 间隔 | 固定 token、上下文、温度、掩码和归约方式 |
| 任务 | 准确率、执行结果、格式/工具参数、长上下文检索 | 冻结答案解析；失败与截断不得删去 |
| 行为 | 长度、重复、EOS、路由、重试 | 帮助解释轨迹分叉与实际成本 |
| 特定架构 | MLA 双路径、循环更新保留、MoE 低频专家 | 不能用平均分掩盖结构性退化 |

PPL 应由有效预测 token 的 NLL 总和聚合：

$$
\mathrm{PPL}=\exp\left(\frac{\sum_i\mathrm{NLLsum}_i}{\sum_i n_i}\right).
$$

不要平均窗口 PPL；不同 tokenizer 的 token PPL 不直接横比。模型生成更短、拒绝更多或更早 EOS，可能提高吞吐却降低任务完成率，需要一起报告。

可使用 Language Model Evaluation Harness 复用标准任务，但仍需核对任务配置、样本输出、few-shot、模板、归一化与后端。它提供结果与逐样本输出保存能力；框架名称本身不能保证你的自定义协议正确。[lm-evaluation-harness](https://github.com/EleutherAI/lm-evaluation-harness)、[任务实现指南](https://github.com/EleutherAI/lm-evaluation-harness/blob/main/docs/new_task_guide.md)。

### 7.7 统计分析：小幅提升尤其要谨慎

1. **先定主要对比。** 在大量配置中找到的最好结果属于探索信号；用独立数据和冻结配置确认。
2. **报告差值与区间。** 相同题目的两个模型，优先保留配对结构；文档内相关时按文档重采样。
3. **分开随机性层次。** 校准抽样、旋转初始化、训练随机性和解码采样不同。能固定的固定，不能忽略的用独立运行测量。
4. **重复次数按问题与成本规划。** 便宜的初筛可以从多个独立种子开始；“固定跑 3 次”并非普遍充分标准。昂贵配置也应说明未覆盖的不确定性。
5. **区分统计与实际意义。** 极小差异可能因样本多而显著，却不值得更高离线成本；反之噪声大时不能把未显著差异说成无损。
6. **非劣检验要先定门槛。** 若允许准确率下降不超过 1 个百分点，应检查差值置信下界是否高于 −1，而不是仅看区间是否包含 0。
7. **多重比较要诚实。** 明确主要任务与探索任务；大规模挑选需要独立确认或合适校正，不仅展示获胜单元格。

**样本量直觉算例：** 对独立配对二分类题，令每题差值 $d_i\in\{-1,0,1\}$、不一致比例为 $u$、真实平均差为 $\Delta$，有 $\operatorname{Var}(d_i)=u-\Delta^2$。当差值较小、采用正态近似时，差值均值的 95% 区间半宽约为

$$
h\approx1.96\sqrt{u/n}.
$$

若 $u\approx0.2$，希望半宽约 0.01，则 $n\approx1.96^2\times0.2/0.01^2\approx7683.2$，应向上取约 7684 题。它只是**区间精度的粗估**，不是显著性检验的功效计算；任务相关、分层抽样、训练随机性和比例极端时需换用合适方法。其含义是：几百道题上的零点几个百分点差异，不应自动当成稳定突破。

### 7.8 性能与资源测量

- [ ] 相同设备、驱动、后端、精度与模型版本；清楚标明硬件能力。
- [ ] 固定 M/N/K、batch、输入/输出长度，或报告真实混合负载分布。
- [ ] 检查真正执行的 kernel，不让静默回退或完整高精度展开冒充低比特执行。
- [ ] 分开加载、离线量化、编译/捕获、预热与稳态运行。
- [ ] GPU 测时正确同步；服务测时还要包括主机、网络与排队边界。
- [ ] profile 用于诊断，普通运行用于发布延迟；replay/采样可能改变执行与缓存。
- [ ] 权重文件、加载峰值、稳态驻留、运行峰值显存分别测量。
- [ ] 报 prefill、decode、TTFT、TPOT/ITL、吞吐与尾延迟，不用其中一个替代全部。
- [ ] 区分固定并发闭环与固定到达率开环负载；记录实际发送率、失败和队列。
- [ ] 既比较固定工作量的系统效率，也比较自然停止下的任务体验；两种结果分开解释。
- [ ] 计入尺度、反量化、旋转、补偿、传输、路由及格式转换开销。
- [ ] 能耗声明需真实测量边界、采样方法和总时长；不能仅用峰值功率乘不匹配时间。

服务的 goodput 应明确是延迟达标请求吞吐，还是另含任务质量门槛；定义不同不能直接比较。vLLM 服务基准源码可用于核对逐次计时、TPOT 和请求 goodput 的具体实现，使用时仍要固定版本。[vLLM 服务基准实现](https://github.com/vllm-project/vllm/blob/main/vllm/benchmarks/serve.py)。

### 7.9 关键消融与压力测试

| 需要排除的替代解释 | 对应实验 |
|---|---|
| 只是校准数据更多 | 相同有效 token 与总选择/优化成本对照 |
| 只是额外高精度容量 | 同完整字节预算、相同例外/补偿开销对照 |
| 只是更长训练 | 等总训练预算与冻结 checkpoint 的分别比较 |
| 只是换了 kernel | 固定量化模型切换后端，或统一参考路径比较算法 |
| 只是挑了一个随机种子 | 多次独立初始化/校准抽样，报告分布 |
| 局部代理更好但任务没变 | 固定前缀、自由生成和任务三层对照 |
| 只适合某个形状 | 小/大 batch、尾块、不整齐维度和长短上下文 |
| 只适合常见任务 | 分语言、领域、长度、难度及低频专家测试 |
| 叠加收益来自另一组件 | 因子实验和交互分析 |

不要为了表格完整穷举所有因素。先根据主张确定最少必要消融，再对发现的异常追加实验。

### 7.10 先确定要估计什么：一个 checkpoint 还是一种方法

<a id="hierarchical-evaluation"></a>

设 $d_{r,i}$ 为第 $r$ 次独立校准/训练得到的模型，在题目 $i$ 上相对基线的指标差。至少有两种不同问题：

- **给定 checkpoint 的测试表现**：条件于已生成的模型，对目标题目分布估计平均差；按题目/文档重采样可以描述这一层不确定性。
- **整个方法重新运行时的表现**：同时考虑校准抽样、初始化、训练和评测随机性；需要独立运行与合适的层次设计。

把所有运行的所有 token 当作独立样本，会虚增有效样本数。如果不同运行评测相同题目，重采样时还要保留题目配对；对交叉的“运行×题目”结构，可使用明确的多层/交叉重采样或统计模型，而不是随意展平成一个数组。

令 $D$ 表示随机运行与随机评测样本共同产生的指标差，全方差公式说明两类来源：

$$
\operatorname{Var}(D)
=\mathbb E_r[\operatorname{Var}(D\mid r)]
+\operatorname{Var}_r(\mathbb E[D\mid r]).
$$

这不是现成的标准误公式，而是提醒你说明哪些变化来自题目，哪些来自方法重新运行。种子数很少时，运行层的不确定性估计本身也不稳定，应明确局限。Agarwal 等在少运行次数的强化学习评测中强调区间估计与稳健汇总；量化可以借鉴其统计思想，但任务结构和汇总方式需要重新定义。[Deep Reinforcement Learning at the Edge of the Statistical Precipice](https://arxiv.org/abs/2108.13264)。

#### 配对 bootstrap 的最小可运行例子

下面只估计**给定两份模型结果、题目独立同分布**时的平均准确率差，不覆盖重新校准或训练的随机性：

```python
import numpy as np

baseline = np.array([1, 1, 0, 1, 0, 0, 1, 1], dtype=float)
candidate = np.array([1, 0, 1, 1, 1, 0, 1, 1], dtype=float)
d = candidate-baseline
rng = np.random.default_rng(20261019)
indices = rng.integers(0, len(d), size=(10000, len(d)))
replicates = d[indices].mean(axis=1)
interval = np.quantile(replicates, [.025, .975])
assert np.isclose(d.mean(), .125)
assert interval[0] <= d.mean() <= interval[1]
print('paired accuracy difference:', d.mean(), 'percentile interval:', interval)
```

8 道题仅用于解释代码，不能提供严肃效果判断。真实文档/会话内题目相关时，应对独立簇重采样，并明确目标是等文档还是等题目权重；改变重采样单位也不能自动解决数据污染或标签偏差。

### 7.11 超参数搜索预算和“最好一次”的选择偏差

<a id="search-selection-bias"></a>

新方法搜索 200 个配置，基线只运行一个默认配置，最后比较两者最佳分数，无法区分方法改进与搜索机会增加。应同时报告：候选空间、搜索算法、试验数、总时间、停止规则、挑选指标，以及是否重用了已有调参结果。

一个更有解释力的结果是**最佳验证质量随总搜索成本的曲线**。冻结选中的配置后，再做独立测试；不能在最终测试集上画“最好一次”曲线来宣布泛化。Dodge 等专门讨论了计算预算如何改变模型比较结论。[Show Your Work: Improved Reporting of Experimental Results](https://aclanthology.org/D19-1224/)。

对同一测试集反复提出假设、挑任务、调阈值，会形成自适应选择。即使没有把测试文本直接喂给优化器，反馈也已经影响了研究过程。适应性数据分析研究说明这种复用需要额外控制；本指南采用可执行的基本策略：探索与确认分离、冻结配置、保留最终未使用数据，并披露已参与选择的结果。[Generalization in Adaptive Data Analysis and Holdout Reuse](https://arxiv.org/abs/1506.02629)。

还应区分三种停止方式：资源耗尽、预定失败门槛、统计停止。不能每跑一批就查看普通固定样本置信区间，看到显著后立即停，并仍按原覆盖率解释；需要预定观察次数/调整方法，或使用适合序贯监测的有效推断。

### 7.12 数据污染、自动裁判与正确率的来源

**数据污染没有一个万能检测器。** 可以检查精确重复、近重复、来源重叠、模板泄漏和生成式训练数据与评测题的关系，但未检出不代表不存在。区分：

1. 基础模型预训练时可能接触测试内容；
2. 量化研究自己的校准/恢复数据与测试重叠；
3. 研究者根据测试反馈选择配置或指标；
4. 自动裁判或答案解析器本身偏好某种输出风格。

同一基础模型的浮点/量化对照能控制部分共同暴露，但仍不能把受污染 benchmark 的成绩等同未见任务泛化；量化阶段新增的数据或教师信号尤其需要检查。

若用 LLM-as-a-judge，应固定裁判版本、提示、评分标准和采样；随机交换候选顺序、盲化方法身份，并用人工核验子集测分歧。控制冗长输出偏好、格式偏好及裁判与生成模型的同源偏差。**裁判一致率高不等于事实判断正确**，人工核验也需给明确标准和复核流程。

代码、数学、JSON 和工具参数任务优先使用可验证的执行结果或结构检查，但“通过测试”只覆盖测试集定义的行为。不要把 schema 合法、字符串匹配或一个单元测试通过等同全部语义正确。

### 7.13 性能数据应有负载分布、计时边界和不确定性

<a id="performance-inference"></a>

**计时前定义观察对象。** 同步 GPU 事件可测某条设备执行路径，主机墙钟覆盖更广的调用开销，客户端请求时间还含排队、网络和流式传输。比较时应使用相同边界，必要时同时报告多种口径。

- **漂移控制：** 监测温度、频率、功率、其他进程和编译状态；采用交替或随机顺序的基线/候选运行，减少“先冷后热”带来的排序偏差。
- **形状覆盖：** 使用目标模型真实形状，也加入不整齐维度、尾块和不同group；预打包或autotuning的成本单列。
- **缓存状态：** cold/hot prefix、L2/权重复用、编译缓存不能混合；测试场景应对应实际使用。
- **时间汇总：** 报逐次数据、样本量和统计方式。微基准多次循环中的迭代可能相关，不能当作大量独立试验。
- **尾延迟：** p99 需要足够请求和明确区间估计；少量运行得到一个p99数字，不代表稳定服务能力。
- **失败与删失：** 超时、拒绝、OOM和仍未完成请求分别报告。只在成功请求上算延迟分位数时，应明确这是条件分布，不能称全请求体验。

对多工作负载加速比，几何平均可以表示某种等权相对改善；但它不是总墙钟加速。若真实流量权重为 $w_j$，更直接的聚合是

$$
S_{workload}=\frac{\sum_jw_jt^{base}_j}{\sum_jw_jt^{new}_j},
$$

其中权重应在观察结果之前按使用场景确定。对在线服务，batch、到达率和缓存命中会改变每请求成本，不能用孤立请求时长机械合成服务吞吐。

### 7.14 比较 Pareto 前沿，不把所有结果压成一个最好数字

将质量、完整显存、延迟、离线成本作为不同坐标。方案A若在全部关心维度不差于B、且至少一项更好，可称在该测量条件下支配B；测量误差跨越差值时，这个支配判断也有不确定性。

建议展示：

- 质量—完整bit/参数，而非只列payload位宽；
- 质量门槛下的吞吐—尾延迟曲线，而非单个最大tokens/s；
- 最佳独立验证质量—总校准/搜索时间；
- 长度/并发—峰值内存，标明OOM与高精度残留区；
- 各任务的成对差值图，同时显示负向变化。

这些图应回答研究问题，不是为了凑齐可视化。对外宣称“更优”之前，先说明哪种资源约束、哪种任务分布与哪条前沿。

## 8. 从实验工程到可复现研究产物

<a id="research-artifacts"></a>

### 8.1 每个关键结果应能追到一次明确运行

建议保存如下关联，形式可以沿用现有工程，重点是内容完整：

```text
论文主张
  → 对应图表与统计计算
  → 原始逐样本结果 / 逐次性能测量
  → 实验配置与运行 ID
  → 代码、模型、数据与环境版本
  → 生成该结果的完整命令
```

- [ ] 模型与数据 revision、tokenizer 和模板版本。
- [ ] 代码 commit、未提交差异、量化配置、随机种子和依赖环境。
- [ ] 逐次计时、实际 token 数、原始预测、失败与跳过记录。
- [ ] 量化器状态、最终 checkpoint、adapter、格式与后端配置。
- [ ] 日志与结果的完整性校验；哈希只能证明一致性，不能证明实验真实。
- [ ] 从原始结果到图表的脚本，避免手工改数字。
- [ ] 小型 smoke 命令与完整复现实验命令，以及预计时间/显存。
- [ ] 清理失败记录前先解释其处置，不能只保留成功运行。

### 8.2 独立复查比“我能再跑一次”更有价值

让一位没有参与实现的人依据说明复查核心公式、基线设置与主图。资源有限时，至少让其完成小模型/小数据版本，并定位哪些完整结果需要额外硬件。若某项实验因访问许可或专有硬件不能公开复现，论文应清楚说明，而不是宣称全部可复现。

NeurIPS 的检查清单要求主张与实际结果相符，并关注理论假设、复现信息、统计不确定性和计算资源披露。这些内容应在研究过程中形成，而不是投稿前临时补填。[NeurIPS Paper Checklist](https://neurips.cc/public/guides/PaperChecklist)。

### 8.3 发布前的最小研究产物

- 一页问题与贡献说明，以及最近工作对照。
- 固定版本的参考实现、优化实现和差分验证。
- 主实验、消融、失败案例与统计结果。
- 模型/数据/代码获取说明和权限条件。
- 运行配置、依赖、设备要求与一键生成关键图表的入口。
- 论文正文、必要证明、实现细节和局限。

不要把整份调研目录直接当作论文附录。论文只保留与主张直接有关的推导和实验；工程教程可作为独立背景资源。

### 8.4 把可复现性分成四个等级

| 等级 | 验证内容 | 仍然不能证明 |
|---|---|---|
| 结果可追溯 | 数字能追到原始结果、代码和配置 | 日志真实、代码正确或结论成立 |
| 同环境可重复 | 相同条件重跑得到符合预期误差的结果 | 跨设备/版本稳定、独立实现正确 |
| 他人可复现 | 另一位读者按说明重建核心结果 | 任意模型/数据上泛化 |
| 独立机制验证 | 独立实现、替代测量或不同条件仍支持机制 | 未验证范围中的普遍最优 |

不同研究类型应明确达到哪一级。不能用文件哈希替代真实性证明，也不能用一个Docker镜像证明实验定义正确。

### 8.5 从变换测试到失败注入：研究代码怎样更可信

除常规输入输出测试，还应建立**保持某种数学关系的变换测试**：

| 性质或故障 | 应检查的结果 | 可发现的问题 |
|---|---|---|
| 关闭量化后的成对缩放/旋转 | 与原浮点函数在容限内一致 | 转置、bias、共享消费者遗漏 |
| pack 后 unpack | 码字、原形状与尾部长度一致 | 符号编码、位顺序和padding |
| 同样编码在新进程重载 | scale、码本和解码输出一致 | 未保存元数据或隐含全局变量 |
| 零输入、全零组、全mask段 | 满足明确定义，不产生伪造有限结果或NaN污染 | 空归约、除零、错误bias |
| 非方矩阵、非整组维度、不同尺度 | 独立参考与优化路径一致 | 广播轴和布局偶然掩盖的错误 |
| 缓存转存或写文件途中失败 | 不留下成功/失败混杂或K/V长度失配 | 非原子状态提交与错误恢复 |
| 仅改变batch组成 | 检查算法是否声明了batch不变性 | 动态范围和异常列并集随batch变化 |

最后一项尤其需要谨慎：浮点矩阵乘可逐行分解，不代表按batch动态统计的量化模型逐行处理后结果完全相同。测试应验证算法承诺的性质，而不是强行要求不成立的不变性。

### 8.6 研究资产应能逐步缩小复现规模

一份完整复现往往需要较大资源。可以提供三级入口：小矩阵数学核对、小模型端到端路径、论文完整配置。三者的输出字段和度量定义尽量一致，使读者能先检查流程，再决定是否投入大算力。

依赖、硬件与数据受限时，提供失败诊断和明确预期；不能静默切到CPU、全精度或较短上下文后仍沿用原benchmark名称。匿名审稿版本也应保留必要信息，同时按当年规则处理作者身份与不可公开数据。

## 9. 算力、时间与协作安排

<a id="resources"></a>

### 9.1 根据可用资源选择研究路线

下面按资源特征给出方向建议，不保证特定模型一定能装入对应显存；校准矩阵、工作区、训练激活和并发都会改变需求。

| 可用条件 | 较适合先做 | 应避免的过度主张 |
|---|---|---|
| CPU 或偶尔使用小 GPU | 数学反例、格式正确性、校准协议、小模型经验研究 | 没有目标 GPU 却声称新 kernel 的真实性能 |
| 单张 16–24 GB 级 GPU | 小/中模型 PTQ、固定格式校准、局部 kernel、有限长上下文研究 | 只用一个小模型就声称跨规模普适 |
| 单张或多张大显存 GPU | 更大模型、长 KV、恢复训练、多个规模的确认 | 将设备更多的结果与少资源基线直接比速度 |
| 稳定多 GPU 集群与系统支持 | MoE、分布式服务、较大规模 QAT、专家通信 | 未控制网络/拓扑/调度便归因于算法 |
| 多人长期算力与训练基础设施 | 原生低比特预训练、较完整 scaling 研究 | 只比较最终适配，不报告全部训练成本 |

资源有限仍可做高质量工作，但应选择能验证的贡献。理论和经验分析也不是“省算力就更容易”：前者要求更强证明，后者要求更严格问题设计与统计。

### 9.2 先做算力预算表

令模型配置数为 $N_m$、方法数 $N_a$、独立种子数 $N_s$，每配置准备/量化时间为 $t_p$，评测条件数为 $N_e$、每条件时间为 $t_e$，一个粗预算为

$$
T\approx N_mN_aN_s(t_p+N_et_e)+T_{search}+T_{failures}+T_{profiling}.
$$

若一次实验同时占用多张 GPU，GPU 小时还要乘并行占用数；时间不一定随卡数线性缩短。相同 checkpoint 可复用的阶段不要重复计，但独立校准种子往往需要重新量化。

**算例：** 2 个模型×4 个配置×3 个种子，准备每次 0.5 GPU 小时、4 个评测条件各 0.25 GPU 小时，基本预算为 36 GPU 小时；再加搜索、失败重跑、系统调试与确认实验。24 次主配置并不等于整个研究只用 36 小时。是否保留 20%–30% 缓冲由资源情况决定，这是规划建议而非统计规则。

### 9.3 时间与协作的实际要求

- **固定研究时段：** 保留连续时间做推导/编码，不把全部时间耗在追新论文。
- **每周一次证据复盘：** 哪个假设获得支持、哪个被否定，下周最小决定性实验是什么。
- **找互补合作者：** 理论、量化实现、kernel、评测或领域数据至少有一项可互相审查。
- **明确职责：** 谁维护基线、谁核验数据、谁检查统计、谁审核图表；贡献和作者安排尽早讨论。
- **找外部读者：** 让不了解项目的人复述你的核心贡献。若只能复述一串方法名，论证主线还不清楚。
- **算力排期：** 最终确认与复现时间应预留，不能在截止前仍依赖一个未跑通的关键后端。

### 9.4 用成本模型决定“先优化哪一层”

<a id="research-cost-model"></a>

一个低比特配置的完整存储至少分成

$$
M=M_{payload}+M_{scale}+M_{codebook}+M_{exceptions}
+M_{KV}+M_{workspace}+M_{runtime}.
$$

训练时还要加入主权重、梯度、优化器和保存激活；存在共享存储时按唯一物理对象计数，存在多个执行布局副本时分别计费。

对一次矩阵乘可用受限的性能近似

$$
t\gtrsim\max(F/P, D/B)+t_{serial},
$$

其中F/D必须覆盖实际执行路径，P/B为该路径可实现的计算/带宽，$t_{serial}$ 是无法被重叠的开销。解码、缩放和搬运可能与计算重叠，因此既不能一概忽略，也不能把所有独立阶段时间机械相加。Marlin 的作者说明展示了离线重排、异步加载、解码与Tensor Core指令调度的配合，可作为“格式节省怎样兑现为速度”的实例，而非通用加速倍数。[Marlin 作者项目](https://github.com/IST-DASLab/marlin)。

#### 一道能改变选题的算账

假设某阶段原来读4 GB数据，有效带宽1 TB/s，其他约束暂忽略，耗时下界4 ms。压缩后含元数据1.125 GB，增加无法重叠的0.5 ms解码，则该阶段为1.625 ms，局部加速约2.46倍。若它只占原总时间60%，整体加速约

$$
S=\frac1{0.4+0.6\times1.625/4}\approx1.553.
$$

这说明：若余下40%已经成为关键开销，再把该阶段的数值格式做得更复杂，未必比优化调度或KV更值得。模型是选题诊断工具，具体数字必须由真实工作负载验证。

### 9.5 校准成本也有可扩展性瓶颈

存一份稠密FP32输入二阶矩需要约 $4d^2$ 字节；d=16384时仅一份矩阵就约1 GiB。分解、拷贝、梯度或多层同时驻留还会增加开销。这与权重是否压到4bit是两个不同预算。

可以考虑流式累积、逐层处理、块对角/对角近似、低秩加对角或随机sketch，但每种策略改变信息量和执行成本。论文应同时回答：减少多少内存/时间，舍弃哪些相关性，对最终任务造成什么影响。

当资源不足时，优先寻找保留核心机制的小规模验证，而不是把所有维度缩小到机制已经消失。例如研究长轨迹状态误差仍需足够长的迭代；研究MoE低频专家仍需覆盖其激活任务；研究Tensor Core布局仍需在支持相应执行路径的设备上验证。

### 9.6 合作分工和研究责任应与证据对应

一种有效分工是：一人负责方法与理论，一人负责强基线/数据评测，一人负责目标后端与性能；小团队可兼任，但核心结论应有交叉审查。

协作中尽早确定代码维护、数据许可、计算预算、作者贡献、负结果保留和对外发布责任。作者资格应基于真实研究贡献与适用规范，不能把单纯资源交换或无实际参与当作默认署名依据。每位作者至少应能解释自己的贡献及其如何支撑论文主结论。

## 10. 候选研究问题、完整案例与启动条件

<a id="candidate-topics"></a>

**以下是值得调查的问题结构，不是已经确认无人研究的创新点。** 本工程已覆盖许多接近的机制；启动前必须再次检索，确认所提变量、约束、目标与现有方法的实质区别。每个方向只有得到新颖性和证据支持后，才可能发展为论文。

### A. 固定部署格式下，校准目标如何改善跨域泛化

- **问题：** 通用校准误差更低，为什么目标代码/中文/长文本任务仍可能更差？
- **额外知识：** 分布漂移、稳健统计、输出敏感性、约束优化与配对评测。
- **最小实验：** 固定模型、位宽、组、尺度精度和后端，比较通用/目标域/混合校准，以及权重/输出/任务感知目标。
- **必要基线：** RTN、同格式的强校准方法、同数据选择预算的简单策略。
- **可能的贡献：** 解释某类代理错配，提出在相同在线格式与离线预算下有效的目标或数据策略。
- **决定性证据：** 在未参与选参的域上重复获益，并定位改善的误差方向。
- **停止条件：** 简单增加或替换校准数据即可解释全部收益；或目标域之外稳定恶化而论文主张仍是通用改善。

### B. KV 量化的收益何时被生命周期成本抵消

- **问题：** 同为 KV4/KV2，窗口、分页、写入与转存时机为何导致不同质量和速度？
- **额外知识：** 流式状态、在线 softmax、内存管理、服务负载与长度分层。
- **最小实验：** 同一权重模型下固定完整缓存字节，比较统一精度、最近窗口、分层位宽或元数据布局。
- **必要基线：** 高精度 KV、目标框架的稳定缓存量化、同预算简单窗口策略。
- **可能的贡献：** 一套成本与误差模型、可执行缓存策略，或揭示常用比较口径的系统偏差。
- **决定性证据：** 长轨迹任务质量、边界正确性和包含转存/读取的真实执行结果同时成立。
- **停止条件：** 需要未计费的高精度副本；缓存容量收益存在，但完整服务质量或延迟目标无法满足。

### C. MoE 的频率、敏感性与共享误差是否能够统一建模

- **问题：** 相同专家排名或相似平均误差，为什么位宽分配仍可能产生不同任务退化？
- **额外知识：** 条件路由统计、敏感性估计、混合预算、相关误差和专家执行。
- **最小实验：** 固定 router，比较统一、随机、频率、直接扰动敏感性分配，再测试 router/共享基变化。
- **必要基线：** 同完整字节预算的统一/随机方案，以及最接近的专家感知方法。
- **可能的贡献：** 找到频率代理失效条件，提出可验证的补充统计或更好的完整预算分配。
- **决定性证据：** 跨任务的低频专家覆盖与真实干预实验，排除额外补偿容量的影响。
- **停止条件：** 只有一个域的少量 routing trace，无法证明所提统计与实际损失相关；或分配成本无法摊销。

### D. 低比特 GEMM 的形状覆盖与布局成本

- **问题：** 一个低比特 kernel 为什么在理想大矩阵快，在真实小 batch、尾块或不同分组下失速？
- **额外知识：** CUDA/Triton、片上布局、流水线、寄存器压力与性能诊断。
- **最小实验：** 固定数值格式和量化权重，扫描真实模型 M/N/K、组大小与 batch，分解加载、解码、计算与归约。
- **必要基线：** 同设备的成熟低比特内核、高精度库实现及合法的 shape-specific 配置。
- **可能的贡献：** 更广形状覆盖的内核/调度，或解释和预测拐点的性能模型。
- **决定性证据：** 完整数值验证、可复查 profiler 证据、模型级收益与调优开销。
- **停止条件：** 只优于刻意低效的 baseline；或只在单个挑选形状上获胜且没有新的系统认识。

### E. 低比特恢复训练中的状态分布与梯度偏差

- **问题：** 教师固定文本上的恢复训练，是否覆盖量化学生实际生成的状态？
- **额外知识：** 蒸馏、重要性采样、score-function 梯度、优化稳定性与序列目标。
- **最小实验：** 固定 checkpoint 和总恢复预算，比较教师文本、学生前缀及简单混合数据策略。
- **必要基线：** 同训练 token/成本的现有恢复方法，以及只改变数据的对照。
- **可能的贡献：** 一个有清晰目标对应的估计器、训练策略，或对现有偏差/稳定性的系统解释。
- **决定性证据：** 明确 KL 方向、采样分布、停止梯度、长轨迹质量和教师/rollout 成本。
- **停止条件：** 把固定前缀梯度证明当完整轨迹证明；或新增数据/教师预算解释了全部收益。

### F. 量化质量评价中被忽略的失败模式

- **问题：** 短文本 PPL 接近时，工具参数、代码执行、停止行为和长推理是否出现系统性差异？
- **额外知识：** 任务构建、统计检验、因果消融、自动评判误差与数据污染。
- **最小实验：** 固定模型/模板与量化配置，保存逐题结果，分开内容、格式、长度与错误类型。
- **必要基线：** 浮点模型、多个代表量化配置，以及控制生成预算/解析规则的对照。
- **可能的贡献：** 可重复且重要的现象、解释其机制的证据，以及能改善评测或选型的协议。
- **决定性证据：** 独立任务、稳健解析、人工核验子集和可复用数据/代码。
- **停止条件：** 只是收集“量化偶尔答错”的例子，缺少发生率、对照、统计和机制。

### G. 多模态量化中的模态不均衡与任务条件

- **问题：** 文本校准稳定，为什么视觉/音频条件任务仍发生退化？量化误差来自模态编码器、连接器还是语言主干？
- **额外知识：** 跨模态表示、模态token比例、预处理与分组件消融。
- **最小实验：** 固定模态预处理和数据划分，分别量化主干、连接器、编码器，比较文本/跨模态任务及中间表示。
- **必要对照：** 同预算的模态平衡采样、随机混合采样、只改变序列长度的对照。
- **可能贡献与停止条件：** 若能定位可重复的模态条件失效并提出相同部署成本的修复，可继续；若只是使用更多模态校准数据导致收益，不能把它包装成未验证的新机制。

### H. 量化导出与编译之间的数值契约

- **问题：** 同一量化器经过转置、分组重排、scale降精度或kernel融合后，为何质量与参考实现不同？
- **额外知识：** 数值语义、IR、图优化、布局、整数累加与重定标。
- **最小实验：** 对固定模型/表示建立独立解码器，逐步改变导出、repack和执行后端，定位第一处数值差异。
- **必要对照：** 同一数据上的QDQ参考、真实打包参考、优化kernel；覆盖非方阵、尾块、半格、饱和和共享权重。
- **可能贡献与停止条件：** 新的正确性方法、可证明保持的变换或解决广泛不兼容问题的执行设计可能有价值；一次个别软件bug修复不自动构成独立研究贡献。ONNX量化算子的类型、轴和分块语义可作为契约的一部分，仍需匹配目标opset及后端。[ONNX QuantizeLinear](https://onnx.ai/onnx/operators/onnx__QuantizeLinear.html)。

### I. 长期记忆与检索的联合压缩边界

- **问题：** 参数查找表、embedding索引、KV和循环状态都占内存，但随机访问与误差路径不同；能否在固定任务成本下分配压缩预算？
- **额外知识：** 检索排序、随机访问、缓存命中、信息保留与状态更新。
- **最小实验：** 先固定一个对象和下游任务，分开测表示失真、命中/排序、读取延迟和最终成功率，再研究两对象组合。
- **必要对照：** 各对象统一精度、仅压一个对象、联合分配、同容量随机/简单分配。
- **可能贡献与停止条件：** 需要揭示访问方式导致的真实预算规律；若只把多个已有开关串联，且没有交互解释或新的约束处理，应缩小为工程应用而非夸大原创性。

### J. 二阶统计的精度、样本数与内存之间如何取舍

- **问题：** 更完整的校准曲率是否总能改进量化，还是在样本少/相关性强时带来估计噪声？
- **额外知识：** 协方差估计、收缩、矩阵扰动、低秩/块近似与随机化算法。
- **最小实验：** 固定量化网格与编码器，比较对角、块、完整及低秩加对角统计，扫描有效校准预算和任务域。
- **必要对照：** 相同统计内存/时间预算、相同数据、仅改变阻尼的基线，以及独立数据上的统计预测误差。
- **可能贡献与停止条件：** 若能解释并预测何时低成本估计更优，或提供有依据的自适应估计策略，可继续；若效果只是不同damping或更多样本导致，需重新界定贡献。

### 优先级建议

如果目前主要资源仍是单卡或间歇性 Colab，建议先从 **A、F 或 J** 做可控制的模型与统计实验，再根据能力转向 B；已有成熟 kernel 或编译经验及目标设备时可优先 D/H。C、E、G 对模型、数据、训练或调试预算要求更高，I 适合已有具体检索/记忆系统的研究者。这个顺序基于关键证据的获得成本，不代表哪类论文更容易录用。

### 一个完整案例：校准 MSE 更低，目标任务反而更差

<a id="worked-research-case"></a>

下面展示的是**研究设计案例**，所有小矩阵数值只用于验证逻辑，不是任何真实模型的成绩，也不是已确认的新颖方法。

#### 第一步：把模糊抱怨改成可测命题

原始观察：“配置A校准更好，但代码能力不如B。”先固定：基础checkpoint、tokenizer、量化格式、scale精度、group、例外层、后端、校准成本、任务解析与解码预算。

若A和B在上述任何关键条件不同，先做匹配对照。否则你还不能确定是目标函数、数据分布还是额外资源造成差异。

#### 第二步：用二维模型证明这种现象在数学上可能

令校准二阶矩与目标二阶矩分别为

$$
C_{cal}=\operatorname{diag}(1,0.01),\qquad C_{target}=I.
$$

两种候选权重误差为

$$
E_A=\operatorname{diag}(0,1),\qquad E_B=\operatorname{diag}(0.2,0.2).
$$

按 $R_C(E)=\operatorname{tr}(ECE^T)$ 计算，校准风险A=0.01、B=0.0404，因此校准选A；目标风险A=1、B=0.08，排序反转。

```python
import numpy as np

C_cal = np.diag([1., .01])
C_target = np.eye(2)
E_A = np.diag([0., 1.])
E_B = np.diag([.2, .2])
risk = lambda E, C: float(np.trace(E @ C @ E.T))
cal = [risk(E, C_cal) for E in (E_A, E_B)]
target = [risk(E, C_target) for E in (E_A, E_B)]
assert np.allclose(cal, [.01, .0404])
assert np.allclose(target, [1., .08])
assert cal[0] < cal[1] and target[0] > target[1]
print('calibration risk:', cal, 'target risk:', target)
```

这个例子只证明**输入分布改变足以造成排序反转**。它没有证明真实代码任务退化就是这一原因，也没有证明任何鲁棒目标必然有效。

#### 第三步：区分三个竞争解释

| 假设 | 支持它的观察 | 能削弱或否定它的对照 |
|---|---|---|
| H1：校准与目标激活统计不匹配 | 独立目标数据上的同层重建排序改变 | 匹配目标统计后仍完全不改变现象 |
| H2：局部输出目标与任务敏感性不匹配 | 重建接近，但某些方向的logits/任务扰动更大 | 等范数不同方向干预对任务没有可重复差异 |
| H3：导出或评测实现改变了函数 | 参考QDQ与重载模型明显不一致 | 独立解码、同输入与同协议核对后差异消失 |

H1/H2可能同时成立。统计相关只能筛选解释；针对不同方向或数据域的干预，才更能区分它们。先排除H3通常比直接设计复杂新算法便宜。

#### 第四步：设计最小决定性实验

固定一个目标模型和同一最终格式，建立至少以下可比较配置：

- B0：稳定的原始强基线；
- B1：只改变校准数据组成，保持有效token与总选择成本可比；
- B2：只改变统计估计/重建目标，保持同一校准数据；
- B3：两种改变一起使用；
- 控制组：随机或简单规则选择同样数量的数据/方向。

先在开发数据确认现象，冻结配置后再用隔离任务测试。若两因素都有成本，除了等token比较，还应补一组等总离线时间或给出成本曲线；单一预算口径无法回答全部问题。

#### 第五步：把评价链串起来

```mermaid
flowchart LR
    A[校准数据和统计] --> B[层输出误差]
    B --> C[固定前缀 logits 与 KL]
    C --> D[自由生成轨迹]
    D --> E[任务成功与总成本]
    F[实际导出格式和后端] --> B
    F --> E
```

每条箭头都代表需要验证的联系，而不是必然单调关系。可以观察层误差改善却任务不变，也可以观察质量稳定但性能变差。这些异常有助于重新定位问题。

#### 第六步：决定是否继续

- 若B1已解释全部收益，则贡献应围绕数据覆盖及其规律，不能把收益全部归给B2的新目标。
- 若B2在开发集好、隔离任务无改善，优先判断过拟合或代理错配，不继续只挑测试子集。
- 若B3显著好于各单因素，应检查交互并确认是否仍在相同完整预算。
- 若参考QDQ好、导出后变差，应回到表示与执行契约。
- 若改善小于不确定性，可增加适当重复/样本，或将结论改为“当前证据不足”；不要把不确定直接等同没有作用。

#### 第七步：组织可能的论文主图

1. 现象图：校准/目标分布下的指标排序与独立重复。
2. 机制图：方向或层干预与误差传播，包含反例或理论条件。
3. 主结果：强基线、同预算的模型/任务结果及不确定性。
4. 消融图：数据×目标函数×导出路径的关键对照。
5. 成本图：校准时间、峰值内存和真实服务性能。
6. 边界图：哪些域、模型或位宽下收益消失或反转。

图的数量可以减少；重要的是每张图回答不同问题，避免多个近似重复的排行榜。

#### 第八步：写出被证据允许的贡献

如果最后只有小矩阵反例，可以说“说明了一个可能的代理失效机制”；如果多个目标模型上的干预支持H1，并有可复现同预算修复，可以提出更强的校准泛化结论。跨架构通用性、固定加速倍数或未知任务无损，仍需要额外证据。

研究的成熟标志是主张能够随证据强弱调整，而不是坚持把最初的想法写成唯一正确解释。

## 11. 24 周研究推进计划

<a id="schedule"></a>

下面按已完成本工程主体学习、每周约 15–20 小时研究投入、能够获得至少一种目标模型验证资源来安排。它是可调整的里程碑模板，**不是 24 周内必然产出论文的承诺**。若算力、数学或工程基础不足，相应阶段应延长；若核心假设失败，应转向，不必机械走完所有周数。

| 阶段 | 时间建议 | 核心工作 | 必须交付 | 继续条件 |
|---|---|---|---|---|
| 0：资源与能力盘点 | 第 1 周 | 自测、确认算力、选择主方向 | 能力缺口表与资源预算 | 关键验证可在可获得资源上完成 |
| 1：方向与文献 | 第 2–3 周 | 精读最近工作、归纳限制 | 文献对照、一页问题说明 | 能写出实质区别和可证伪问题 |
| 2：强基线复现 | 第 4–6 周 | 跑通完整量化—重载—评估 | 可复查的基线结果与偏差解释 | 基线质量/成本合理，流程稳定 |
| 3：现象与机制 | 第 7–9 周 | 诊断、反例、最小干预 | 一张机制图/表或关键推导 | 现象可重复，主要混杂已排除 |
| 4：方法原型 | 第 10–13 周 | 设计目标、实现参考与格式路径 | 算法/理论草稿、正确性检查 | 改进来自明确机制，预算可比 |
| 5：确认与泛化 | 第 14–18 周 | 冻结配置，独立任务与模型验证 | 主表、消融、统计与失败案例 | 主张有足够证据，边界明确 |
| 6：真实执行 | 第 19–21 周 | 目标后端、内存、负载与复现 | 系统证据或清晰限定的部署范围 | 性能主张有真实数据；独立复查可行 |
| 7：论文与复查 | 第 22–24 周 | 写作、内部评审、补关键缺口 | 完整稿、附录、代码包、投稿清单 | 没有关键未解释失败或证据断点 |

系统论文应把后端可行性和 profiler 工作提前到阶段 2–3；理论论文应尽早证明主结论，再设计与理论有关的验证；低比特训练论文需要更早确认训练成本和稳定性。表中的先后顺序可以调整，但不能把核心可执行性留到最后。

### 前 30 天最值得完成的十件事

1. 选择一个主方向，以及一个明确目标模型/格式/工作负载。
2. 写出自己尚不具备的三项关键能力，并安排对应短练习。
3. 建立最近相关工作对照，识别至少一个可能的实质限制。
4. 跑通浮点基线，确认 tokenizer、模板、任务解析和计分 token。
5. 跑通一个强量化基线的保存、重载与模型级质量。
6. 有目标 GPU 时测实际后端；无 GPU 时明确不做性能结论。
7. 保留逐样本结果，找到一种可重复而非偶然的失败模式。
8. 设计一个能否定当前解释的干预实验。
9. 估算后续确认实验的总成本，包含失败重跑。
10. 请一位同伴检查“一页问题说明＋一份基线结果”，再决定是否继续。

### 每周复盘的五个问题

- 本周新增了什么可验证知识，而不只是多跑了多少实验？
- 当前最重要的未解释现象是什么？
- 哪个替代解释最可能推翻我的主张？
- 下一个最小且决定性的实验是什么？
- 继续、缩小范围、改变假设还是停止，依据分别是什么？

### 按论文类型调整里程碑，而不是机械套用周数

- **理论主线：** 尽早得到一个准确、可证明且非平凡的命题。若核心假设只对不现实分布成立，应先改问题，不能用大量模型实验掩盖理论脱节。
- **校准算法：** 第一个完整模型流程与强基线应尽早跑通；尚未验证真实导出时，不值得扫描大量量化超参数。
- **系统主线：** 目标硬件、格式布局与瓶颈必须前置确认；没有实际kernel路径时，后面的服务收益只是估计。
- **经验主线：** 先冻结测量问题、任务分类和解析规则；核心贡献应是新认识和可靠证据，而非不断追加任务。
- **训练主线：** 先用小规模验证稳定性与预算口径，再扩大模型。失败率、教师成本和中断恢复应进入计划。

每一阶段应保留“停止、缩小、改解释”三种合法出口。长时间没有形成可检验知识时，优先反思问题是否过宽或关键证据不可获得，而不只是继续投入更多GPU小时。

## 12. 论文写作、投稿与答辩

<a id="writing-submission"></a>

### 12.1 写作应伴随研究，而不是所有实验结束后才开始

建议早期就写一页问题说明和贡献草稿，但使用“假设/待验证”标记未完成的主张。主图出来后重写故事，使摘要和结论围绕最终证据，删除已经放弃的机制解释。

| 部分 | 应完成的任务 | 常见问题 |
|---|---|---|
| 标题 | 准确指出对象与贡献 | 用“无损”“最优”“通用”超出实际范围 |
| 摘要 | 问题、方法/发现、主要结果和适用条件 | 只列最大倍数，不交代模型/设备/质量约束 |
| 引言 | 说明限制为何重要，核心洞察如何解决 | 先堆背景，最后才说做了什么 |
| 相关工作 | 对照最接近机制、目标与条件 | 只按时间列论文，没有解释区别 |
| 方法/理论 | 变量、目标、算法、复杂度、假设与证明关系 | 正文与代码的量化轴/符号/目标不一致 |
| 实验 | 回答主假设，排除混杂，说明失败与边界 | 只有最好结果，没有公平基线与消融 |
| 局限 | 精确说明不能推出什么，以及当前验证范围 | 将所有限制泛泛写成“未来扩大规模” |
| 附录与产物 | 复现细节、证明、完整配置和额外分析 | 把理解核心贡献所必需的全部内容藏到附录 |

### 12.2 主结果表应让读者知道“付出了什么”

量化算法表建议同时包含：模型、完整格式、组/尺度、例外与补偿、校准/训练预算、任务质量、完整内存和对应后端。系统表还应说明形状、batch、长度、资源、冷/热状态和计时边界。

若摘要写“最高加速 X 倍”，正文必须指出它发生在哪个配置，另外给出代表性工作负载的分布或汇总；不能用一个极端有利点暗示所有场景都达到相同倍数。合理基线、质量门槛与未加速部分比修饰词更能支撑说服力。

### 12.3 选择投稿方向

以下是定位建议，最终应阅读**目标年份与具体 track**的官方 CFP；本指南不把 2026 年规定当作未来投稿规定。

- 偏通用学习算法、量化理论或训练机制，可考虑 ICML、NeurIPS、ICLR 等相关主题，但必须匹配具体贡献与证据。
- 偏低比特运行时、内核、编译、缓存或服务系统，可重点研究 MLSys 及相关系统会议的范围。MLSys 2026 CFP 明确覆盖高效训练/推理/服务、LLM、编译器与运行时等主题。[MLSys 2026 CFP](https://mlsys.org/Conferences/2026/CallForPapers)。
- 偏语言能力、任务评测和行为分析，可研究相关 NLP 会议/期刊的当前范围，不能假定“用了 LLM”就自动符合其核心关注。
- 尚在早期的小规模研究可以考虑合适 workshop 获取反馈，但应清楚区分 workshop 与主会论文；不能把它当作高质量的替代证明。

### 12.4 投稿前必须检查当前官方规则

- [ ] 截止日期与时区、摘要注册与全文提交是否分开。
- [ ] 页数、模板、匿名要求，附录、代码与补充材料的提交边界。
- [ ] 审稿范围、贡献类型和 track，是否需要额外声明。
- [ ] 作者与机构信息、利益冲突、作者列表修改规则。
- [ ] 同时投稿、先前发表、预印本和相关稿件的规定。
- [ ] 可复现性、计算资源、局限、数据来源与许可证说明。
- [ ] AI/LLM 使用披露；不能把其他会议的规则直接套用。
- [ ] 研究涉及数据隐私、人工评估或受控数据时，完成适用的审批与授权。
- [ ] 如果提交代码/权重/数据，检查是否有权分发、是否符合匿名要求。

ICLR 2026 作者指南鼓励复现说明，并对匿名及显著 LLM 使用披露有具体要求；MLSys 2026 CFP 将被接收论文的 artifact evaluation 列为自愿参与。二者不能泛化为所有年份、所有会议统一要求。[ICLR 2026 作者指南](https://iclr.cc/Conferences/2026/AuthorGuide)、[MLSys 2026 CFP](https://mlsys.org/Conferences/2026/CallForPapers)。

### 12.5 内部评审与 rebuttal

请同伴分别扮演三类审稿人：熟悉最近工作的量化研究者、会检查预算和执行路径的系统研究者、会追问统计与任务有效性的评测研究者。无需真的有三个团队，重点是覆盖不同审查角度。

收到质疑时：

1. 先判断是误解、表达不足、实验缺失还是实际错误。
2. 用明确公式、配置、图表或新增受控实验回答。
3. 承认并修正真实问题；限制主张比争辩一个不成立的结论更可靠。
4. 区分原稿已有证据与回复阶段新增结果，不把后者说成原本已经完成。
5. 不承诺在资源和时限内无法完成的大规模实验。

**提交时机的判断：** 论文已能完整回答一个重要问题，主证据可复查，最近工作区别清楚，主要失败已解释。不要仅以“截止到了”或“结果比基线高一点”作为唯一依据。

### 12.6 如何用一段话说清楚真正的贡献

<a id="contribution-writing"></a>

可用以下结构组织初稿，但只填已经获得的证据：

> 在明确场景C下，已有方法A受到限制L。我们通过观察/推导发现机制M，并据此提出改变I。与最接近工作相比，差别在目标/约束/执行路径X。在固定预算与独立评测下，结果支持结论Y；在条件Z下该结论不成立或尚未验证。

逐句审查：删除其中的算法名称后，是否仍能说明新增知识？如果只能说“组合了几个模块、比一些基线高”，需要回到问题价值与机制，而不是继续修饰标题。

理论贡献应指出相对已有界放宽了什么假设、收紧了什么界或新增了什么可计算结论。系统贡献应指出哪个真实瓶颈被改变、为什么已有设计不能得到同样收益。经验贡献应指出哪个认识被改变，以及别人可以如何据此改进评测或决策。

### 12.7 审稿人可能提出的十二个决定性问题

1. 最近哪篇工作最接近？换个符号是否已经包含你的方法？
2. 你解决的限制在多少真实使用情景下重要？
3. 为什么这个目标函数对应你声称的任务，而不仅是方便优化？
4. 精度收益是否来自更多校准数据、搜索或高精度容量？
5. baseline为什么可信，复现偏差如何处理？
6. 理论的随机/独立/光滑/网格假设在实现中满足吗？
7. 导出后是否仍是相同函数，是否存在隐藏高精度副本？
8. 哪个消融最能排除你的主要替代解释？
9. 跨模型或任务的结论是否由足够独立证据支持？
10. 报告的误差条包含哪些随机性，是否存在多重选择？
11. 速度包含哪些阶段，失败/超时和tail latency是否计入？
12. 哪个结果会使你承认这项方法不适用或贡献不足？

在投稿前请合作者按这十二个问题审查主图和贡献，优先修复影响结论的证据缺口。文字润色只能改善表达，不能替代缺失的实验或错误的推导。

## 13. AI 辅助研究的核验要求

<a id="ai-research"></a>

本工程大量使用 AI 辅助整理。AI 可以加快阅读、推导、代码原型和写作，但作者仍应对事实、证明、实验、引用与原创性承担责任。

### 13.1 可以让 AI 帮忙，但必须独立核验

| AI 产出 | 人需要完成的核验 |
|---|---|
| 文献摘要 | 打开原论文，确认标题、版本、方法与实验范围；摘要不能替代相关章节 |
| 公式推导 | 写出假设、单位和形状；用独立推导/求解器/反例验证关键步骤 |
| 代码 | 与参考实现做差分检查；避免只写与错误实现同源的测试 |
| 实验分析 | 回到原始输出、计时、失败记录和统计单元，不采信自动生成的数字 |
| 新颖性判断 | 检索同目标、同约束和等价机制；AI 的“从未有人做过”不是证据 |
| 论文文字 | 每个主张对应证据，逐条核对引用，避免拼接未验证叙述 |

- [ ] 不引用不存在或未核验的论文，不让题名相似替代原文确认。
- [ ] 不用 AI 生成“看起来合理”的 benchmark、表格、引用数或运行日志。
- [ ] 对 AI 提出的反例或证明进行独立计算；不能让同一模型自问自答充当全部验证。
- [ ] 对模型输出作为训练数据、标签或裁判的用途，记录模型版本、prompt、采样与成本，并验证误差/偏差。
- [ ] 不把他人的未公开稿件、数据或代码上传到未经授权的外部服务。
- [ ] 按目标会议规定披露使用范围，尤其是参与研究构思、核心方法或实验评价的用途。

### 13.2 披露要求并不统一

截至本指南核对的公开规则，NeurIPS 检查清单关注 LLM 作为核心方法中重要、原创或非标准组件时的说明；ICLR 2026 作者指南还要求披露达到显著贡献程度的研究构思和/或写作辅助。**不能简单采用“只润色所以任何会议都不需要说明”的统一结论。** 提交时重新核对目标年份规则，并如实描述工具参与的环节与人工验证。[NeurIPS 检查清单](https://neurips.cc/public/guides/PaperChecklist)、[ICLR 2026 作者指南](https://iclr.cc/Conferences/2026/AuthorGuide)。

专业成长的验收不是“能让 AI 生成一篇论文”，而是你能够在没有 AI 代答的情况下解释：为什么问题重要、方法为何合理、实验如何排除替代解释，以及结果在哪些条件下不成立。

### 13.3 建立独立验证，避免同源错误互相确认

AI生成的方法、测试和解释如果都基于同一错误理解，可能彼此通过却一起偏离真实定义。关键位置应引入不同来源的验证：

| 被验证对象 | 同源检查容易漏什么 | 更独立的方式 |
|---|---|---|
| 二次优化公式 | 同一转置/常数错误在推导与代码中重复 | KKT方程、独立求解器与小规模穷举 |
| 量化布局 | 编码器和解码器共享同一个错误排列 | 官方格式字段、手工字节例子、另一实现 |
| 任务分数 | 生成结果与AI裁判共享风格偏好 | 执行验证、盲化人工子集、顺序交换 |
| 性能解释 | 看到加速就自动归因于预期机制 | 时间线、内核证据、单因素与反事实控制 |
| 新颖性 | 只检索相同术语，遗漏等价目标 | 改用问题/数学/约束关键词检索并人工比较 |

还应区分“AI提出的猜想”“人工确认的推导”“实际执行的结果”。论文中只将后两类证据用于支持对应主张；AI给出的置信语气不是研究证据。

## 14. 分阶段总检查清单

<a id="master-checklist"></a>

使用方法：只有完成实际交付或有可检查证据时才勾选。没有适用的项目可以注明原因；不要为了“清单全绿”补造实验。下面的门槛服务于研究管理，不是会议验收标准。

### G0：可以开始选题

- [ ] 能独立完成量化核心推导与完整存储账本。
- [ ] 能阅读目标模型、量化器与后端的关键源码。
- [ ] 明确目标方向、可用算力、时间和需要的合作者。
- [ ] 能跑通目标模型的浮点评测。
- [ ] 已选定一项可在当前资源上完整验证的问题。
- [ ] 已识别最接近工作，而非只看综述中的经典方法。
- [ ] 明确额外知识缺口与短期学习产出。

### G1：可以投入方法开发

- [ ] 最近工作对照已说明相同与不同之处。
- [ ] 一页问题说明包括可证伪假设和停止条件。
- [ ] 至少一个强基线完整跑通保存、重载与评估。
- [ ] 主要现象能在独立重复或不同样本中再现。
- [ ] 简单基线/随机对照未解释掉所有现象。
- [ ] 关键数据与实现可合法获得。
- [ ] 主要验证预算包括失败、消融与独立确认。

### G2：可以启动大规模确认

- [ ] 方法与最接近工作存在经核查的实质区别。
- [ ] 参考实现、实际表示和高效路径的关系清楚。
- [ ] 主公式、约束和证明已经过独立检查。
- [ ] 无隐藏高精度副本或未计入的额外容量。
- [ ] 校准/训练预算与基线可比，差异明确列出。
- [ ] 小规模结果足以支持继续，而不是只有一个最好样本。
- [ ] 已冻结主要评测协议与确认配置。
- [ ] 预先确定主要指标、质量门槛和统计单位。
- [ ] 关键失败会被保留并解释。

### G3：可以形成论文主结论

- [ ] 主表回答的是预先提出的研究问题。
- [ ] 每项主要主张有对应的理论或实验依据。
- [ ] 使用了最接近的强基线并解释复现偏差。
- [ ] 主要消融排除了数据、容量、训练预算、kernel 和调度混杂。
- [ ] 模型/任务/长度覆盖与主张范围相符。
- [ ] 主要差值有适当不确定性说明。
- [ ] 已报告实际存储、加载/运行峰值及离线成本。
- [ ] 性能主张来自真实后端，不是模拟或理论上限。
- [ ] 失败模式与不可泛化条件已经写清楚。
- [ ] 未见测试未被用来持续选择方法。

### G4：可以提交并接受复查

- [ ] 最近工作和同时期论文已再次核对。
- [ ] 摘要/引言/结论与最终证据相符，无超范围“最优/无损/通用”。
- [ ] 代码、模型、数据与环境版本可追溯。
- [ ] 原始结果可重新生成主图表，无手工修改分数。
- [ ] 至少一位独立读者复查了关键实验或证明。
- [ ] 全新目录的 smoke 复现通过，完整复现要求清楚。
- [ ] 全部作者理解核心贡献并确认内容与署名。
- [ ] 目标年份模板、匿名、提交、利益冲突与同时投稿规则已核对。
- [ ] 适用的数据、许可、伦理和 AI 使用说明已完成。
- [ ] 已预留答辩与关键补充实验的时间和资源。

### G5：深度与广度是否匹配主张

- [ ] 区分了权重、层输出、概率、轨迹与任务误差，没有跨层直接推断。
- [ ] 明确所用二阶统计的定义、样本单位、归约方式与估计误差。
- [ ] 解释了跨层、跨专家或跨时间误差的交叉项何时可忽略。
- [ ] 检查了多模态、检索、工具或长上下文中与主张相关的独立能力维度。
- [ ] 分开了固定checkpoint质量与重新运行方法的随机性。
- [ ] 报告了超参数搜索成本与配置选择过程，而非只给最好一次结果。
- [ ] 数据污染、裁判偏差、失败删失及负载分布均有对应处理。
- [ ] 性能模型与实测互相解释，临时内存、转换、通信和服务成本没有遗漏。
- [ ] 至少一个强替代解释被决定性实验排除，至少一个不适用条件被明确指出。
- [ ] 理论、方法、系统与经验结论分别具有所需证据，没有为了广度强行扩大范围。

### 16.2 三条按产出组织的阅读路径

**校准算法路径：** 从GPTQ的固定输入重建出发，读任务敏感性/Fisher的条件，再读经验统计偏差与搜索预算。产出是一个固定格式、固定成本的目标比较实验，能够解释数据和损失各自的作用。

**系统路径：** 从真实模型形状与完整内存账本出发，读Triton/CUTLASS分块和Marlin解码调度，再用Nsight与服务基准核对瓶颈。产出是数值正确、包含完整成本的执行对照，而非只会调用量化加载接口。

**状态与评测路径：** 从KV/MLA/循环状态误差出发，读行为诱导分布、长上下文任务构造和分层统计。产出是能区分固定前缀、状态反馈与任务失败的实验，而非只收集长回答案例。

每条路径都应把原始文献、自己推导的结论和实际运行结果分开。跨方向阅读用于找到缺失变量与约束，不需要把所有工具和理论都塞进同一篇论文。

**基于当前工程的行动建议：** 先完成一个真实模型强基线及其保存重载和评测，写出一页可证伪问题卡，同时补齐统计评测与目标后端知识。只有当小规模实验显示新颖且可解释的信号时，才扩展模型规模、训练预算和论文范围。这条路线能减少无效准备与无效大实验，也更容易形成可信的研究贡献。
